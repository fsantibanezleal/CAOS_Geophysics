## Stable accumulation and attainable precision

Native terminal gradient4.9835795212782585e-12, compensated flattened evaluation4.985244422134327e-12, exact domain2 gradient4.988299035020833e-12. Simply replacing sums with fsum does NOT meet1e-12 at this current model: the gradient is genuinely above the frozen exception, not just cancellation noise. Flattening/rounding coefficients in this comparison is separately labelled; it is not our proposed source-preserving evaluator.

The harness evaluates a conservative serial binary64 residual/gradient error bound on the flattened, coefficient-rounding-inclusive graph using `u=2^-53` and `gamma_k=k*u/(1-k*u)`. For residual row j:

`e_rj <= sum_i |Bji-round64(Bji)| |qi| + |cj-round64(cj)| + gamma_(2a+2)*(sum_i |round64(Bji) qi| + |round64(cj)|)`.

For each gradient coordinate, propagate these residual bounds through `2 w B.T r`, coefficient/weight conversion errors, each dot-product gamma_(2m+2), and final weighted-block gamma_(2blocks+2). The harness performs bound arithmetic rationally. Terminal bound is7.201766061170485e-13. This is NOT automatically a bound for SimPEG's different nested BLAS/CSR operation graph or a tight lower bound on unavoidable error. Underflow/overflow or unverified reassociation invalidates a transferred proof; production would have to propagate errors through its actual graph or refuse certification.

Nearest-q representation has the separate rigorous bound `||g(round64(q*))||inf <= max_i sum_j |Hij| ulp(q*_j)/2`, here2.2004363298104816e-14. This is an UPPER bound demonstrating attainment at this optimum, NOT a proof that every rounded point must have that error. Actual native and exact nearest gradients are far below1e-12. Absolute1e-12 is therefore attainable for THIS frozen control. There is no proof of universal attainment over all admitted scales/dimensions: the quantization bound and residual-accumulation errors depend on H, q, coefficient magnitudes, row counts and operation graph.

Actual Windows NumPy longdouble has53 significand bits,8bytes, identical to float64. Casting to longdouble on this reviewed runtime is NOT extra precision. Decimal directed intervals or proven error-free product/sum expansions are alternatives requiring their own bounded implementation/source/runtime review.
