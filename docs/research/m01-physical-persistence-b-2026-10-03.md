## Fresh primary references and interpretation

- [Linux man-pages flock](https://man7.org/linux/man-pages/man2/flock.2.html): advisory locks attach to open file descriptions; duplicated/forked descriptors affect lifetime and conversion is not an atomic upgrade. B forbids conversion/inheritance and needs actual whole-tree proof, not a PID list.
- [Microsoft LockFileEx](https://learn.microsoft.com/en-us/windows/win32/api/fileapi/nf-fileapi-lockfileex): shared/exclusive ranges, same-handle overlapping behavior and delayed release after termination need exact handle discipline. B's separate candidate binding is not proof Windows directory durability or child association works.
- [SQLite opening connections](https://www.sqlite.org/c3ref/open.html): open flags/cache/VFS behavior distinguish normal existing-file access from immutable assumptions. B refuses create/attach/network-filesystem fallback and binds actual native identity separately.
- [SQLite PRAGMA reference](https://www.sqlite.org/pragma.html): FK/synchronous/read-uncommitted/busy settings are connection behavior needing readback. B proposes FULL/FK/explicit transactions, not a claim current app already pins them.
- [SQLite WAL](https://www.sqlite.org/wal.html): committed changes can be in WAL; DB/sidecars must be read coherently, not separately hashed as immutable scientific files during bookkeeping. Excluding writers does not make stale sessions fresh.
- [Python3.12 sqlite3](https://docs.python.org/3.12/library/sqlite3.html): explicit transaction policy and connection versions are part of an actual driver proof. B pins a candidate CPython3.12 control approach, leaves approved SQLite build unregistered until actual isolated tests.
