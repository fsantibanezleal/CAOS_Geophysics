# Earthquake P/S phase picking: M08, M13 and browser input

Status: M08/M13 offline STEAD evaluation and a frozen M13 ONNX export are prepared on the separate M13 branch. This frontend sidecar implements real browser inference and a local parity gate; model, waveform and sealed metric assets are supplied separately. The local gate passed on the finalized 23 QC-valid display traces, but this branch makes no public release or deployment claim. These methods use earthquake station waveforms, not active-source shot gathers for acoustic FWI.

## Data and physical units

The future input chain is a rights-reviewed MiniSEED waveform, matching StationXML channel response, event/station identity and independently sourced analyst phase picks. MiniSEED digital samples are counts. A response-corrected derivative may be ground velocity in m/s only when channel, epoch, stabilization and output-unit choices are documented. The original bytes remain immutable: ObsPy response removal changes an in-memory stream in place. Each selected window records UTC start, sample rate `f_s` in Hz, three-channel order/orientation, gaps, clipped samples, response epoch, detrend/taper/filter/resampling operations and hashes of the original and derivative. The sample timestamp is `t_n=t_0+n/f_s`; `n` is dimensionless and `t_n` is UTC time. A count trace must not be labelled m/s. [ObsPy response lookup](https://docs.obspy.org/packages/autogen/obspy.core.inventory.inventory.Inventory.get_response.html), [response removal](https://docs.obspy.org/packages/autogen/obspy.core.stream.Stream.remove_response.html), [FDSN StationXML](https://docs.fdsn.org/projects/stationxml/en/latest/).

## M08: classical onset and phase association

For a consistently labelled channel `x[n]`, a classical characteristic compares short and long squared-amplitude averages. `N_S=round(f_s T_S)` and `N_L=round(f_s T_L)` convert window durations in seconds to sample counts, with `N_L>N_S`. The ratio `C[n]=mean_short(x^2)/mean_long(x^2)` is dimensionless whether `x` is counts or m/s, but invalid denominators, gaps and incomplete long windows are not valid detections. Trigger-on/off thresholds propose intervals, not phase labels. P and S association requires a separate, documented phase window and component/polarization evidence; held-out analyst labels must not choose the prediction. An S candidate can be confused with P coda or a converted phase; choosing the second trigger is not a physical classifier. A published S workflow adds polarization, AR-AIC refinement and quality checks, but these are not frozen M08 settings. See [Allen's 1978 onset picker](https://doi.org/10.1785/bssa0680051521), [ObsPy classic STA/LTA](https://docs.obspy.org/packages/autogen/obspy.signal.trigger.classic_sta_lta.html), [ObsPy trigger source](https://docs.obspy.org/_modules/obspy/signal/trigger.html), and [Diehl et al.'s S-wave picker](https://doi.org/10.1785/0120080019) with its [reproducibility supplement](https://www.seismosoc.org/Publications/BSSA_html/bssa_99-3/2008019-esupp/).

The frozen M08 comparator uses 0.12 s STA, 1.2 s LTA, ratio threshold 2.5 and 0.4 s P–S separation on the selected STEAD windows. A result must retain candidate onset, P/S pick or unresolved reason, channel evidence, ratio/threshold, preprocessing and source hashes. Comparison to an analyst pick yields signed `delta_t=t_pick-t_analyst` in seconds, not a comparison to an exact physical arrival. This simple energy-ratio detector is a comparator, not a reliable physical P/S classifier.

## M13: PhaseNet-family learned picking

[Zhu and Beroza's PhaseNet paper](https://doi.org/10.1093/gji/ggy423) describes three-component, per-component mean/std normalized input; its reference data were sampled at 100 Hz and its illustrated window has 3001 samples, or 30.0 s between endpoints. The network adapts a 1D U-Net with four downsampling and four upsampling stages and skip connections. At each sample, softmax scores for background, P and S sum to one. Analyst picks become Gaussian-smoothed targets with a 0.1 s reference width, and categorical cross-entropy sums over classes and time. The [official AI4EPS code](https://github.com/AI4EPS/PhaseNet) is a reference, not a bitwise-identical implementation of the local model.

The selected local encoder-decoder accepts 60 s at 100 Hz, exactly 6000 samples of measured E/N/Z unrestituted counts. For each component, the processor computes the mean in float64, casts both mean and samples to float32, subtracts in float32, then divides by the float32 peak absolute centred count. This turns the input dimensionless; it is **not** the paper's standard-deviation normalization. Flat or exactly duplicated components fail QC. A pre-normalized curated trace is passed to ONNX without another normalization. The browser rejects other rates, lengths, orientations, units, missing channels, gaps and declared clipping; it does not resample or response-correct. P and S are global class maxima accepted at fixed score 0.8, with S abstaining if its peak is less than 40 samples after P. These scores are not calibrated uncertainty. Analyst disagreement, time-base error, out-of-distribution instruments, low SNR and overlapping events require separate analysis.

## Disjoint same-trace evaluation and release boundary

The approved Geophysics SDD demands a stricter test than the PhaseNet paper's station-stratified recording split: training, development and test have no event ID overlap **and** no station identity overlap in the selected STEAD inventory. A bridge recording whose event and station belong to different partitions is excluded and counted. This is the local split protocol, not a published PhaseNet result.

M08 and M13 receive identical held-out trace IDs, windows, QC flags and analyst picks. The locked benchmark has 6,000 selected records; 5,926 are QC-valid and 74 QC rejections remain in its denominator as unpicked. One-to-one phase matching uses a predeclared 0.5 s tolerance. Its sealed artifact carries per-phase precision, recall, false picks, misses, P/S confusions, signed and absolute timing residuals, stress cases and source strata. The 24 browser-display records were selected from metadata before test scoring: 23 have valid normalized waveforms and one NC/AV noise trace failed for a flat component. That record remains visible without a waveform or prediction and is never replaced. The 24 are not the benchmark denominator. Softmax calibration remains separate from timing agreement.

The local browser parity script executes ONNX Runtime Web on all 23 public-display waveforms and compares its unrounded full N/P/S arrays with the private frozen PyTorch oracle. The gate requires maximum absolute probability difference `<=0.001` and peak-time difference `<=1` sample at the fixed thresholds, retaining the QC failure. Against the sanitized-model manifest SHA-256 `d4d2b5b1a98d3a7a2077baab7750c8a96e4b5152b6930e4a09ae4bdc97db8394`, the local Chromium run measured maximum `4.41e-6` and zero peak-sample difference across 23. This establishes numerical parity for the local browser configuration on the predeclared display subset; it does not certify a public deployment, calibrated scores or accuracy on arbitrary user uploads.

## Browser input and asset contract

The six-page app places a live M13 instrument on Benchmark. A user may supply a `.onnx` file and a JSON trace with schema `caos.phase-browser-trace.v1`. The JSON must give `trace_id`, source label, `sample_rate_hz: 100`, `component_order: ["E","N","Z"]`, `representation: "counts"` with `unit: "counts"` or `representation: "normalized"` with `unit: "dimensionless"`, and `channels` containing E, N and Z arrays of exactly 6000 finite samples each. Its `qc` object must assert `components_measured: true`, `gaps: false`, `clipped: false` and `response_corrected: false`. These assertions are user-supplied and do not prove external provenance or sensor quality. The browser rejects unsupported/ambiguous data with a reason, never fills a missing channel, and does not infer a catalogue pick from labels.

The separately tracked `data/derived/phase/browser-assets/stead/manifest.json` uses `caos.phase-browser-assets.v1`. Its `input` and `output` name the `[1,3,6000]` ENZ and N/P/S tensors. `model` names `model.onnx`, byte count, checkpoint and ONNX SHA-256, and fixed thresholds. `benchmark` names a hash-checked 6,000-record sealed metric JSON. `selection` preserves the 24/23/1 population. Each `qc-valid` record names a 72,000-byte `trace-XX.f32` with SHA-256, little-endian float32 and component-major ENZ layout. The `qc-rejected` record has `qc_reason` and no waveform asset. The frontend only fetches same-origin, manifest-named files; it verifies model, benchmark and waveform hashes before use. The canonical asset copy into the Vite public directory belongs to the M13 export branch; this sidecar does not create or alter those files.

The instrument plots measured normalized E/N/Z and the browser's N/P/S scores against relative seconds, with accepted model picks and separate manual analyst references. Hover reads exact sample values; plotting reduces only the display envelope after the full probabilities have been validated and peaks chosen. Export writes all 18,000 little-endian float32 scores for independent checking. A local model or trace is labelled as unverified and cannot inherit the sealed benchmark claim. A selected QC-rejected record disables inference and clears stale plots.

Run the independent local browser gate with `node frontend/scripts/verify-phase-browser-parity.mjs --assets <canonical-asset-directory> --oracle <private-oracle-directory>` from `frontend/`. The oracle directory is ignored private storage and is read directly by Node; it is never copied into public assets or committed. Run `node frontend/scripts/qa-phase-picker-live.mjs --assets <canonical-asset-directory>` against a built bundle for rendered EN/ES and light/dark checks. Browser parity should be rerun whenever the manifest, model, normalized waveform bytes, runtime version or postprocessing code changes.
