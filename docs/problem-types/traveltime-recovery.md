# Koenigsee first-arrival traveltime recovery (M09)

Status: local, `provider-link-only` field QC and **conditional predictive inverse**. The source and all per-pick/model output are ignored locally; this is not a public field case, waveform/FWI computation, validated geological section or rights clearance. The [feature SDD](../design/features/m09-koenigsee-traveltime/requirements.md) fixes the gates; the [source guide](../guides/05_sources.md#m09-koenigsee-first-arrival-tomography-local-only) gives acquisition commands.

## Data and physics contract

The [official pyGIMLi Koenigsee example](https://www.pygimli.org/_examples_auto/2_seismics/plot_04_koenigsee/) treats `koenigsee.sgt` as field seismic-refraction first-arrival picks. The pinned file has `N # shot/geophone points`, `#x y`, N positions, `M # measurements`, `#s g t`, and M source/receiver/time rows. The IDs are 1-based in the file. It contains no seismic waveform, amplitude, pick uncertainty, geographic CRS, explicit coordinate/time unit or absolute elevation datum. This vertical declares the provider-compatible **local** interpretation `x,y` in metres, `t` in seconds and velocity in m/s; it does not claim the file declares these. The local y axis is the surveyed 2D topographic coordinate used by the numerical operator, not a regional elevation model. Strict source parsing rejects nonfinite, duplicate, self, out-of-range, zero/negative or truncated picks instead of repairing them. Gross apparent-speed and same-side time-order anomalies are *flags*, never automatic exclusions or error weights. No field reciprocal pair is present, so reciprocal precision is unavailable.

For speed `v(x,z)>0` and slowness `s=1/v` in an isotropic high-frequency first-arrival approximation, the travel-time field from a source obeys the eikonal equation `|∇T|=s` away from the source, with `T(source)=0`. Along a minimum-time path `Γ`, `T_g=∫_Γ s dl`. In the homogeneous limit, `T_g=||r_g-r_s||/v`; thus the predicted time is reciprocal under source/receiver exchange and halves when speed doubles. The local independent control computes this Euclidean limit separately and compares it to pyGIMLi's Dijkstra forward result on a flat grid to relative error at most `10^-3`. This checks units, sign and basic operator geometry, not a heterogeneous velocity model or ray-bending accuracy at every field scale. The [pyGIMLi traveltime manager documentation](https://www.pygimli.org/_modules/pygimli/physics/traveltime/TravelTimeManager/) defines `t` and absolute `err` in seconds and supplies the Dijkstra/regularized-inversion implementation.

## Field inverse and out-of-sample test

The offline operator uses all surveyed x/y positions, a pyGIMLi 2D parameter mesh, `secNodes=3`, `paraMaxCellSize=5`, `zWeight=0.2`, a 500-to-5000 m/s gradient start, regularization `lam=20` and maximum 20 iterations. It fixes one engine thread and checks repeated prediction/mesh agreement rather than silently replacing an immutable receipt. The fitted quantity is positive speed; the objective balances weighted travel-time mismatch against spatial regularity. `sigma_t=max(0.03*t,0.0001 s)` supplies **assumed** weights because the source provides none. The 3% component matches the library's fallback scale; the 0.1 ms floor is a local numerical/pick-quantization assumption, not an instrument precision. A fitted chi-square is conditional on these weights and cannot calibrate uncertainty or validate a subsurface structure.

Two **predeclared whole-shot** tests fit different training subsets: every fifth shot in sorted x order (indices 4, 9, 14 of 15), and a second fit holding the three central shot-order indices (6, 7, 8). In each test, the baseline is a single homogeneous slowness fitted by weighted least squares on *that split's training picks only*. The inverse uses no held-shot pick. After fitting, a **fresh** Dijkstra manager predicts all source/receiver pairs on the frozen inverse mesh: the training-only manager has no ray graph for withheld sources, so changing its data container is not a valid held-shot forward test. Its training prediction must agree with the original inversion response. The signed residual convention is `predicted-observed` seconds; absolute-time RMSE in seconds/ms is computed over all held picks and separately by held shot.

The predictive gate requires a finite positive model and predictions, a normal engine stop before the iteration ceiling, at least 10% aggregate held-out RMSE improvement against the matching baseline in **both** partitions, and at least two of three held shots improved in each. Failing one gate retains QC and attempted metrics locally with a failed status. An alternate 700-to-3500 m/s gradient start and a finer 2.5 m parameter-cell target are predeclared sensitivity runs, not choices made by inspecting held-shot performance. Mesh identities, starting options, engine versions, source/code hashes, observed/predicted pick arrays, group splits, residuals, stopping history, model and coverage vectors and a receipt checksum support local reproduction. The script never writes these field arrays to a tracked output directory.

The reported coverage is summed **training-ray path length** through parameter cells. Zero coverage means no training ray crosses that cell under the fitted model; positive coverage does not measure resolution, uncertainty or uniqueness. Different regularization, start and mesh choices may change a plausible velocity section. Held shots still share receivers, field conditions and one short 2D profile with training; they test within-profile prediction, not independent-site generalization. Unmodelled source/receiver statics, 3D structure, anisotropy, wrong picks, first-arrival ambiguity, elevation datum and the assumed noise scale remain limitations. No inferred low-velocity layer, sharp interface or geological identity is declared truth. A future public presentation needs an explicit provider/data-rights decision, calibration evidence and a separately reviewed scientific release gate.
