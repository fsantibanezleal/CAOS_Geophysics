# Selected-project processing workbench design

## Authority and scope

Baseline: `origin/develop` dce92a1, with the approved product SDD and merged API processing implementation. Governing conventions read before code: Entry_point, stack selector, ADR-0011/0012/0016/0017/0071 (shared shell, bilingual controls, theme and instrument sizing), ADR-0044 (existing cookie auth), ADR-0069 (scientific evidence boundaries), ADR-0075 and spec-driven development (requirements/design/tasks before implementation). This feature uses the existing six-page React/Vite application and same-origin ApiClient; it adds no backend implementation or canonical scientific artifacts. The user has explicitly renewed implementation and scoped this frontend vertical.

The actual API's `geophysics.observation-dataset/v1`, `geophysics.processing-request/v1` and `geophysics.processing-result/v1` are narrower than the future product ObservationDataset/SolverJob/ResultArtifact mirror. They get a separate TypeScript module, preserving actual schemas and scope. Gravity QC is the actual `app.compute.flag_gravity_stations` calculation, run by the existing separate CPU worker. It flags `abs(g - median(g)) / (1.4826 * MAD(g)) > threshold`, leaves observations/sigma unchanged, and fails for a degenerate scale. The browser validates returned output but never substitutes its own result for a job.

## App selection and authenticated state

ProjectDrawer retains account/project/raw upload/receipt administration and adds an explicit Open processing workbench action. It hands the selected project UUID to App and closes. The App route then gives its main instrument to that project; curated case replay is available through a labelled return action. A `?project=<UUID>` query records selection on the existing App route and permits refresh/bookmark hydration. It contains no credentials and grants no authority. The component probes the real cookie session and verifies ownership from projects before displaying private data. Logout/401 clears project content; opening the drawer supports signing in again. Legacy static build keeps its existing curated behavior.

A project component owns transient session, raw assets, dataset receipts/payload, method verdicts, job history, selected job/result, parameter draft and view/cursor state. Reads carry AbortSignals and effects discard stale responses. A dataset switch clears the old result immediately. An admitted job retains its returned request threshold even if the next-run draft changes. Lists refresh while active jobs exist; an observed terminal state stops polling. Failed/cancelled jobs show typed errors without a result panel; network errors offer retry. Selection/unmount aborts reads, not server jobs. Cancellation is a distinct CSRF-protected API operation.

## API and data flow

`POST /api/projects/{id}/datasets {asset_id}` performs real server row/physical validation. Upload adds an optional explicit sigma-column field for gravity: raw-only originals without sigma remain supported, but processing explains why they are ineligible. Dataset receipts, full payloads, methods, job lists/read, POST jobs/cancel and GET result/export are all parsed and bound to requested identities. Unsafe requests use the existing cookie/CSRF transport. Errors preserve API code and field locations with EN/ES guidance.

Eligibility is server-derived. The frontend supports submitting only the versioned gravity flag operation and its bounded threshold. Other methods remain visible with server reasons; a future eligible method unsupported by this frontend is explicitly labelled rather than submitted using a guessed parameter shape. This seam lets the concurrent MT backend evolve without editing app/ or inventing M05/M06 contracts here. No send_input tool is exposed to this session; exact MT frontend support requires a separately versioned reviewed payload from that work.

Job responses contain resource estimates/limits and timestamps/usage, but no fractional progress. The UI displays queue/running/cancellation-requested/terminal facts. Only `succeeded` may request a result; a success result must agree with dataset/job/request identities, unchanged observations/sigma, axes/units/rights, code digest, statistics and flag semantics. Solver prediction, inverse residual, sensitivity and model views are unavailable for this processing schema.

## Primary instrument and export

A compact control sidebar groups data validation, run configuration and history. The main station instrument occupies the majority of the remaining App surface. Geometry and observed/score charts use the existing SVG scientific widget approach for at most 4096 discrete stations; explicit axes, sigma bars, flagged shapes, linked selected-station readout and accessible paged station table accompany them. Pointer/touch/keyboard selection, brush zoom, pan, zoom/reset and display controls are local view operations. No station is excluded and no coordinate/value/unit is inferred. All colors and fonts inherit shell tokens. Phone controls collapse independently of the instrument; document scrolling remains contained.

The actual API export contains only ZIP_STORED `manifest.json`, `dataset.json`, `result.json`. A bounded ZIP parser from a published library verifies member sizes/names and SHA-256 over original member bytes, then strict typed parsers and identity/semantic checks before download. The real exported bundle is also checked by the independent Python verifier in local browser QA. No original raw CSV or private storage paths appear in this export. No canonical artifact is regenerated by tests/build.

Its ZIP uses source/environment and parser/forward receipts and is not verified by the gravity-only bundle verifier. No MT result is routed through the gravity parser or plotted as observed gravity.
