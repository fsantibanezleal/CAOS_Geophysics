# Selected-project processing workbench requirements

Date: 2026-10-03. Status: implemented and locally verified for the bounded gravity flag adapter. Parent: approved product SDD R-004/R-005/R-006/R-011; issues #74/#75. Implementation authorized by the user's October 3 bounded frontend assignment. This unit consumes the existing authenticated processing API; scientific engines and their release gates retain their own acceptance criteria. Exact receipts and non-claims are in [validation.md](validation.md).

R-PW-01 WHEN an authenticated owner opens a selected project from the existing App project drawer, THE frontend SHALL show its datasets, eligibility, jobs and results on the primary App instrument without adding a route, replacing shared shell typography/tokens, or mixing curated results with private observations. Gate: `frontend/e2e/processing-workbench.spec.ts` test `owner upload to flag result and verified export` and test `direct project hydration and session boundary`.

R-PW-02 WHEN a gravity original declares an uncertainty column, THE upload UI SHALL preserve that explicit column in the raw metadata and offer server dataset validation; IF it is absent or the server rejects rows/units/geometry, THEN THE frontend SHALL explain the failing fields without claiming a valid scientific dataset. Gate: `frontend/src/test/upload-metadata.test.ts` test `preserves optional gravity sigma declaration without guessing`; `frontend/e2e/processing-workbench.spec.ts` test `invalid rows and failed processing remain non-success`.

R-PW-03 WHEN dataset/eligibility/job/result payloads arrive, THE frontend SHALL parse the actual versioned API contracts, reject type/shape/unit/state/path/identity drift and foreign project/dataset/job responses, and keep those separate from future SolverJob/ResultArtifact contracts. Gate: `frontend/src/test/processing-contracts.test.ts` test `rejects identity shape physics and fake inverse drift`; `frontend/src/test/processing-client.test.ts` test `binds all replies to the requested project dataset and job`.

R-PW-04 WHILE a dataset is selected, THE frontend SHALL derive eligibility from the API, retain unavailable methods and reasons, and submit only the implemented gravity flag method with a finite threshold in [1,10]. The submitted parameter and source dataset SHALL remain inspectable with the immutable job request. Gate: `frontend/src/test/processing-client.test.ts` test `submits explicit parameters with CSRF and abortable same-origin reads`; `frontend/e2e/processing-workbench.spec.ts` test `owner upload to flag result and verified export`.

R-PW-05 WHEN a job is queued/running, THE frontend SHALL poll its observed state and account/project history, display returned resource preflight and measured usage, and offer actual server cancellation; WHEN it reaches success or non-success, THE frontend SHALL stop active polling and retain the terminal state/error. No percentage progress SHALL be invented. Gate: `frontend/e2e/processing-workbench.spec.ts` test `queued cancellation and poll recovery`; `frontend/src/test/processing-contracts.test.ts` test `validates state dependent job fields`.

R-PW-06 IF the session expires, the project/dataset/job selection changes, a request fails, or the component unmounts, THEN THE frontend SHALL abort/discard stale reads, clear private observations when authorization is lost, preserve actionable inputs on ordinary errors, and expose a retry. Gate: `frontend/e2e/processing-workbench.spec.ts` test `direct project hydration and session boundary`; `frontend/src/test/processing-client.test.ts` test `forwards abort and typed transport failures`.

R-PW-07 WHEN validated observations or successful flag output are present, THE frontend SHALL plot actual station geometry, observations and sigma in declared units, mark the returned flags, and link pointer/touch/keyboard station selection with exact values and an accessible table. Zoom, pan, brush and reset SHALL affect only display. Gate: `frontend/e2e/processing-workbench.spec.ts` test `linked station controls and viewport fit`.

R-PW-08 WHEN a flag result is shown, THE frontend SHALL preserve observations and sigma, identify robust scores as dimensionless statistical QC, show the exact submitted threshold and lineage, and state that prediction/residual/model are unavailable in this contract. It SHALL NOT call this M01 complete or an inversion. Gate: `frontend/src/test/processing-contracts.test.ts` test `rejects identity shape physics and fake inverse drift`; `frontend/e2e/processing-workbench.spec.ts` test `owner upload to flag result and verified export`.

R-PW-09 WHEN a successful processing export is requested, THE frontend SHALL fetch the real authenticated ZIP and verify bounded members, schemas, member hashes and result/dataset/job identity before offering the download. Gate: `frontend/src/test/processing-contracts.test.ts` test `verifies processing export and rejects tamper`; `frontend/e2e/processing-workbench.spec.ts` test `owner upload to flag result and verified export` plus `app.bundle.verify_bundle` on that downloaded ZIP.

R-PW-10 THE selected-project workflow SHALL remain operable in EN/ES and both themes at desktop and phone sizes, with labelled controls, visible errors, six shell routes and viewport-contained App layout. Gate: `frontend/e2e/processing-workbench.spec.ts` test `linked station controls and viewport fit`; `frontend/src/test/foundation-routes.test.ts`.

Scientific boundary: this closes only the frontend consumption of the flag-processing contract for #74/#75. M01 corrections/inversion, full solver result evaluation, MT activation, actual-host release benchmarks and public deployment remain their separate product gates.
