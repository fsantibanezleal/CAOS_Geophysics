# Host harness design

Research precedes this unit: Python resource limits at https://docs.python.org/3/library/resource.html define RLIMIT_AS as mapped address space, not RSS, and RLIMIT_FSIZE as each file, not total scratch. The existing worker additionally samples child-tree RSS and total private scratch. The server's installed systemd 255 manuals were inspected on 2026-10-03 because upstream freedesktop manual access returned 403. `ProtectSystem=strict` needs explicit writable paths; `MemoryMax` is a cgroup last line of defence, not a replacement for application admission. Preserve the runtime's numerical ceilings.

Use a task-specific immutable staging directory outside production under `/opt/fasl-admission/geophysics/`. A root operator verifies/upload-installs reviewed source and dependencies, then a transient service runs under DynamicUser with a private StateDirectory, no network access/listener, restricted address families and writable state only. The service has 2 GiB cgroup ceiling, zero swap, two CPU cores maximum and a 30-minute timeout. Parent/API plus child must fit the service. Scientific-library thread counts are one.

Tests share existing harness contracts and capture mail locally only for isolated accounts. Twenty fresh nominal job attempts per method use the same immutable supplied EDI, fixed scientific parameters and actual child executables. The sample includes first imports; repeated warm caches do not substitute a cold run. While a real job runs, owned read endpoints are requested and timed. A monitor samples available host RAM, free disk and the process tree every 50 ms. The result states this is TestClient/application responsiveness, not nginx/public TLS evidence.

The real crash control starts `app.worker` as a distinct subprocess with storage-only settings, observes a real `app.mt_compute` child, kills the parent, waits for closed-stdin orphan protection, and calls normal recovery. No instrumented command replaces the real crash child. Existing fault-injection tests separately verify enforced timeout, cancellation and RSS/scratch codes. Every receipt includes code/source/runtime/resource identities; a failure never becomes a passing admission statement.

Server setup and execution are operational actions in the authorized product scope, not a new public deployment. Originals, failed outputs and immutable runtime directories are preserved. The full release convergence ledger remains independent and non-passing until all product requirements close.
