# Actual-host admission requirements

Scope: approved SDD sections 3 and 8, R-007/R-017. This unit measures the existing M05/M06 runtime on the ML VPS. It never changes public nginx, DNS, Pages, production private state or online activation flags.

- HA-01: WHEN invoked explicitly on Linux under a non-root restricted identity, THE harness SHALL execute the existing authenticated API and singleton numerical worker, with immutable job/result identities. Gate: `tests/api/test_host_admission.py::test_nominal_distribution_and_concurrent_reads`.
- HA-02: THE harness SHALL measure at least twenty nominal jobs per admitted method, nearest-rank p95 wall/RSS/scratch, parent-plus-child RSS, minimum host available memory and disk, and enforce nominal usage below 70% of configured limits. During the run, measured headroom SHALL cover the explicit worker, API, bootstrap-controller and one-job scratch byte budgets. The separate pre-cutover inventory SHALL measure the candidate release, current plus two rollback releases and existing project bytes, then require free disk to cover candidate release plus configured job scratch and available memory to cover worker, API and controller reservations; current retained/project bytes are already reflected in free space and SHALL NOT be deducted twice. No universal whole-host percentage applies. Same-process TestClient responsiveness is labelled separately from public HTTPS responsiveness. Gate: same test plus `verify_single_vps_release.validate_capacity`.
- HA-03: THE host SHALL pass original nominal/upper/malformed controls without changing numerical limits or scientific resolution. Gate: `tests/api/test_online_mt_benchmark.py::test_local_nominal_upper_malformed_admission` on this host, not a copied Windows receipt.
- HA-04: WHEN the real worker parent is killed during a child job, THE orphan SHALL exit and recovery SHALL persist a non-success result, preserve disputed staging, and successfully process a new attempt. Gate: `tests/api/test_host_admission.py::test_real_parent_crash_and_recovery` plus existing cancel/timeout/resource gates.
- HA-05: EACH server method-class runner SHALL use an immutable reviewed source archive, isolated pinned venvs, transient DynamicUser identity, strict filesystem and process/cgroup bounds, no listener and only private writable admission state. Gates: reviewed `scripts/server_mt_admission.sh` and `scripts/server_gravity_l2_admission.sh`, actual systemd property receipts and adjacent tests.
- HA-06: THE guide SHALL preserve raw receipts and explicitly exclude whole-product/public-host activation claims until integrated HTTPS, account/ownership, security, scientific and browser gates also pass. Off-host backup and restore are deferred by the approved operating amendment and are not release gates. Gate: `tests/api/test_host_admission.py::test_host_guide_contract`.
