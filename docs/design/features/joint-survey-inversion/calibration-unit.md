# Actual public optimizer composition and frozen calibration ledger

The public nonlinear seam is independently versioned, not the linear gravity
certificate. The trusted adapter exposes the reviewed thirteen-key identity and
seven methods in the nonlinear seam contract. A baseline has one normalized
property block, own training data and volume/active-face regularizer. Joint
states have two blocks, both training data terms and the actual quartic. Fixed
initial diagonal is computed from the genuine PSD sparse CrossGradient Hessian;
free metric is its reciprocal on exact sorted free indices and zero elsewhere.
No diagonal jitter, sensitivity weighting or private optimizer helper is used.

For reproducible actual float64 comparisons the adapter retains F's original
literal left-associated five-operand evaluation. Components expose phi_d,
phi_m, phi_engine and the exact weighted engine_terms tuple. Regrouping to
phi_d+phi_m is not assumed bitwise equal; the five unweighted terms remain
separate. No objective value, precision predicate or tolerance is changed.
Every solve shares the original complete-workflow monotonic deadline. Actual
resource checkpoints surround evaluations and operator actions; allocation
declarations do not replace the separately measured budget.

The driver admits only `JointDevelopmentProblem`, never a sealed/truth argument
or caller solver. It executes sixteen real baseline fits then ten positive
lambda/two-start joint fits with the frozen candidates and exact selection rule
in algorithms.md. Failed attempts remain in the ledger, including their last
accepted states. If a modality has no stationary baseline the driver records
failure and refuses a frozen optimized selection. The uncoupled comparison is
the exact concatenation of selected separately fitted models, no fake lambda0
refit. If no positive eligible candidate exists, its reason is explicitly
`no_validated_coupling_benefit`; neither validation selection nor KKT implies
geological recovery or global optimum.

Ledger keys: schema=`joint-survey-calibration-1`, plan_sha256,
development_sha256, optimizer_binding, source_inventory, allocation_plan,
status, reason, candidates (ordered tuple), selected_baselines, selection,
calibration_sha256. Each candidate binds declared stage, modality, beta values,
lambda, start kind, objective identity, public result, physical trace and five
term trace, validation WRMS values, stationarity verification and eligibility.
Trace states are native bounded arrays, not a list of arbitrary JSON callbacks.
The ledger hash excludes only its own hash slot and binds all states/failures.
Selection is frozen before sealed evaluation; a provided-model evaluation never
becomes an executed inverse because its hash/origin label was changed.

The CLI is a private local processing tool, not a deployment/activation tool.
It requires an external data root from explicit argument or environment, input
and output confined under that root, and explicit external scratch root. Its
commands are solve, evaluate, validate. Unknown/abbreviated flags, nonfinite
weights, existing outputs and cross-input aliases reject. Evaluation reads an
already frozen supplied model, compiles real physics and exports actual marginal
metrics without claiming inversion. Solve never opens sealed values until the
actual calibration succeeds and frozen.json is durably written. Validation
replays actual physical evaluation and, for a solved artifact, verifies the
calibration record too. No overwrite, public raw export or browser activation.

An interrupted driver exports `aborted.json` under envelope
`joint-survey-aborted-calibration-file-1`. Its native payload binds the plan,
development, exact source inventory and optimizer binding, the replay-verified
candidate prefix and, when returned by the public solver, the genuine last
attempt BEFORE subsequent scientific replay. Each trace array has a fixed
candidate or last-attempt name. The payload explicitly says
scientific_replay_completed=false and inverse_completed=false. Phase flags
distinguish a durably written freeze from an attempted sealed read. The separate
failure.json records the adverse measured resource state; it cannot be accepted
by the completed-workflow validator. Previously written files are retained,
never overwritten or deleted. Failure recording does not reset the deadline,
retry a fit, manufacture convergence or open a not-yet-read sealed partition.
