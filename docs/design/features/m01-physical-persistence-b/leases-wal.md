These are candidate native bindings requiring actual proof, not source-document capability claims.

Acquisition uses bounded nonblocking retries with monotonic30-second total deadline. Failure means `physical_writer_busy`; no fallback locking/DB mutation. Lease does NOT expire while a writer is alive. Cancellation of acquisition leaves no DB transaction/file write. Cancellation of a holder first quiesces its handler/stream/child and disposes DB resources; unlock LAST. If quiescence is uncertain, do not claim release safety or proceed with classification. OS close/process death alone does not prove descendants stopped writing; independent native containment/drain proof is mandatory before exclusive recovery.

Shared lease is task-scoped with explicit nested reference count; same task may reuse its outer shared lease, but no new native descriptor/conversion. Concurrent tasks acquire independent descriptors/handles. Exclusive leases are non-reentrant, cannot be upgraded from shared and cannot be requested with any DB transaction/worker lock held. Spawned compute never inherits lease FD/handle or a live DB connection; CLOEXEC/noninheritance PLUS actual spawn/fork/handle tests required. Fork while a lease is held is unsupported; use reviewed spawn with close_fds and no pass_fds. Worker parent retains shared lease for the entire child lifetime, wrapping and cleanup. Exact lock order: global lease -> worker singleton lock if relevant -> fresh DB connection/BEGIN IMMEDIATE -> filesystem action. Release DB resources -> worker lock -> global lease. Worker iteration obtains/relinquishes both global and singleton around claim/execute/cleanup, NOT singleton first across the idle loop. Recovery holds exclusive global, then nonblocking worker singleton probe; any unexpected holder is a refusal, not a deadlock wait. Never hold a DB transaction while waiting for global lock. No timer releases a still-active writer's lock.

## 5. Exact disposition and cuts

For coherent committed, preserve scientific state and immutable files. Only verified cleanup of already-recorded custody is eligible; never remove a possibly published destination or rewrite success as failure. For prepared/uncommitted, explicitly authorized abandonment atomically transfers every installed pending target and stage to A custody, retires targets then intent/reservation, updates allocator and terminal failure/cancel where applicable. Unsealed stage keeps full reservation/quarantine until complete inventory/reap proof. No source hashes/UUIDs are recycled. Old empty prepared-root family is deleted ONLY after transfer, leaving no scientific root.

For precommit deletion abandonment, exact recorded rename reversal restores each still-owned moved file to its original unoccupied path; no overwrite/copy/merge. Recheck original row/file hashes under exclusion and durably sync before retiring the empty deletion preparation. Any existing destination/ambiguous partition -> inconsistent; preserve both. An uncertain reversal commit needs a NEW fresh classifier, not assumed rollback.

Each action uses a new explicit write transaction after classification's transaction ends, retaining exclusive native lease. Revalidate the complete decision descriptor/hash before mutation and commit. Any connection/commit error disposes that connection and returns to fresh classification, never an unlink-in-finally guess. Legacy recover_interrupted may run ONLY after new physical classification/disposition establishes a clean inventory; it must not change physical states via its old all-running update. Dispatch its mutation to legacy method IDs only under the same lease and source-reviewed handler. Capture refuses any unresolved intent/reservation/custody charge.

The A cut matrix is fully covered by these predicates: reservation/preparation/install/final/terminal/deletion/cleanup commit boundaries use fresh classification; partial output has no visibility; stage debt after success is retained; cleanup absent-name alone is not removal proof.
