# Source-original linear arithmetic

`physical_original_quadratic` is a closed trusted in-process arithmetic module,
not a new optimizer, source admission, arbitrary factor callback or nonlinear
acceptance policy. Existing optimizer epochs and archived receipts are unchanged.
An independent physical-domain check remains the adapter's obligation: a linear
map alone cannot certify a magnetic total-field norm or its direction domain.

## Original operands and operation order

The exact13 native identity and `OperandBinding` bind source, objective,
allocation and the actual model. Original bounds, physical scale, beta,
smallness and all fixed smoothness weights retain their scientific meaning.
The first term must be positive diagonal smallness with identity derivative.
Unknown maps, affine offsets, nonlinear norms and quartic coupling are refused.

The map is the original stored binary64 sensitivity `G`, either directly or
followed by a stored unit three-component direction for each grouped vector.
Projection is nested **after** `G q`; no rounded projected matrix is substituted.
Its adjoint expands the direction before applying `Gᵀ`.

`diagonal_sd` uses original positive standard deviations and two directed
divisions in the gradient, never rounded reciprocal multiplication.
`stored_lower_cholesky` uses the actual native stored lower factor and original
covariance. Exact symmetry, lower storage, positive pivots, original condition
number at most `1e8`, and byte-exact native Cholesky consistency are required.
Forward and reverse triangular substitution preserve the original nesting.
No inverse, jitter, alternate covariance or caller-supplied SPD assertion exists.

For original map `C` and whitening `Z`, the real extension is

`F(q) = c ||Z(Cq-d)||² + β Σⱼ αⱼ ||Wⱼ Dⱼ(q-reference)||²`,

where `c` is the literal `1` or `0.5`. The original source gradient is enclosed
using `2c CᵀZᵀZ(Cq-d)` and each separately nested fixed regularization term.
It does not replace the native physical gradient or native Hessian action.

The actual stored-real chord is `dq = qt-q`, not a rounded manufactured search
step. `certify_chord` encloses `2yᵀdy + ||dy||²` for each original term, requires
strictly negative **recorded native-gradient** slope and strict original Armijo
margin with `1e-4`, and retains the original14-key certificate contract.
The precision ladder is34/50/80 digits; a fast outward binary64 row enclosure
at34digits precedes pure Decimal work without changing a sign or tolerance.
Expiry, zero displacement, non-descent, unsupported range and exhausted
precision remain failures, never successful fallback.

## Storage and claim boundaries

Metadata/backing counts precede numerical scans and factor checks. Scalar/source
counts are bounded, full covariance has at most512 components, and canonical
float64/int32 CSR factors have at most `8 * parameters` entries per matrix.
Ultimate ndarray backing is counted even for a small view; foreign buffer
storage is refused. Both operand payloads and sparse transpose/copy storage,
endpoint buffers, native row scratch and metadata are itemized independently.
The loaded Decimal endpoint-pair closure is checked before arithmetic; the
arithmetic phase is bounded by the literal source resource budget together with
the original kernel maximum. The8MiB reserve is a minimum, not proof of every
larger phase. Returned dictionary accounting is **not** measured RSS, native
allocator containment, online host authority or a full workflow acceptance.

Unit controls use independent Fraction objectives/gradients, original nested
projection and triangular solves, strict chords and actual rejection cases.
Physical fit qualification additionally needs unchanged independent model,
objective, prediction and KKT assertions and actual native residual/cap replay.
Full-matrix acceptance also requires a stronger source-owned terminal certificate
within the **same** original fit deadline. This module supplies no such global
terminal theorem, nonlinear/GN exemption or accepted full-matrix receipt.
