# Paired source bundle design (proposal before code)

## Boundary and input protocol

Implement only NEW `scripts/ops_source_bundle.py`, `tests/ops/test_source_bundle.py` and builder guide/convergence after MAIN review. Reuse frozen `ops_source_pin` validation/caps read-only; no existing verifier/core/runtime edits. The builder runs on MAIN's trusted local Git-owning workstation, not the archived Linux runtime. Explicit runtime and ops Git roots may be different worktrees/repositories, but each resolves to its own actual repository root. Neither selected content nor application code is imported/executed. No checkout/stash/reset/fetch/clone/install/service/archive extraction, no package and no global Git trust change. Dubious ownership fails closed; the operator must use an already authorized local repository, not a wildcard trust exception.

Proposed CLI:

```text
--runtime-repo /explicit/local/git/root
--runtime-commit FULL_REVIEWED_40_HEX_COMMIT
--ops-repo /explicit/local/git/root
--ops-commit FULL_REVIEWED_40_HEX_HOST_FEATURE_COMMIT
--selection /explicit/private/main-reviewed-selection.json
--selection-sha256 INDEPENDENTLY_REVIEWED_SELECTION_SHA256
--epoch EXPLICIT_NONNEGATIVE_NORMALIZED_UNIX_SECONDS
--new-output /explicit/private/NEW-bundle-directory
```

Selection schema proposal: `geophysics.ops-source-selection/v1`; exact keys `schema runtime_commit ops_commit files`; `files` exactly `runtime ops`, each a sorted unique relative-path list. Full commits must match CLI identities, no branch/tag/ref selectors. Selection is MAIN-reviewed before building, not automatically trusted because a server calculates its hash. No broad filesystem glob, arbitrary secret path or one-size-fits-all repo archive. Minimum sets are frozen `REQUIRED_RUNTIME`/`REQUIRED_OPS` from the reviewed HFIX verifier; MAIN explicitly adds the full app import closure from the chosen commit (including auth/formats/models/security/processing/project/view/schema/error modules). Additional files need exact reviewed paths in the selection, not prefix blanket admission. Permit only selected `app` source/config/migrations, named Python pipeline dependencies, exact API fixture helpers, required ops code and two required original public EDI fixtures. Deny env/credential/key/backup/download/private/SQLite/native/bytecode/package artifacts and mode variants. Public EDI fixtures are the necessary named exception to the no raw-intake policy, not permission to bundle surveys or downloads. MAIN review is responsible for all secret absence; filename/magic/private-key marker checks are defensive gates, not an exhaustive secret scanner.

## Immutable Git object reads

Use bounded read-only Git commands with explicit roots and full object IDs. Disable replace-object interpretation and clear inherited Git environment selectors/config injection/alternate object overrides; do not change Git config. Confirm root/object format and exact commit type, parse its immutable tree reference, and use NUL-delimited tree inventory for exact selected paths. Modes must be100644 or100755 and object type blob; reject120000 links/160000 gitlinks/nonblob/ambiguous paths before any output. Do not apply checkout filters, textconv, LFS hydration or filesystem symlink resolution. An LFS pointer cannot substitute for a required source fixture; reject pointer content. Read exact object bytes via bounded `cat-file` using the verified blob OID, never `Path.read_bytes()` on the mutable working tree. Check reported size against fixed limits before streaming, verify actual streamed byte count, SHA-256 and Git blob-object identity against its header/content/OID. Standard Git content-address hashing is integrity/provenance only, not custom encryption or an authentication claim. Root tree/commit and every selected blob/mode/path are retained in a separate receipt so MAIN can independently repeat Git-object verification.

Dirty/untracked worktree changes are intentionally irrelevant and preserved; tests must prove committed bytes win even if files are replaced/deleted or a sentinel/key appears in the worktree. Unknown/replaced commits, missing blobs, link/submodule modes, corrupt object content or inherited repository redirection must fail closed. No read of keys, native dependencies or raw production state is authorized. The trusted Git executable/helper launch source and actual repository ownership remain MAIN prerequisites; no script can establish trust in its own already-corrupt executable.

## Deterministic paired archive and publication

Prevalidate selection/commits/object modes/sizes, caps, explicit output/parent scope before creating output. Output parent must already be owner-private/trusted and outside repositories, production/served/vault/backups. Create the exact NEW output directory atomically with0700; every file uses exclusive creation0600, no overwrite. Existing or linked target/parent, source overlap or invalid epoch fails without modifying existing data. A failed newly created output remains private diagnostic state with no completion receipt; no automatic broad deletion/cleanup.

Stream each verified blob into stdlib USTAR in sorted scope/path order. Emit FILE headers only, uid/gid0, empty uname/gname, mode0644, one explicit integer epoch for every member, empty PAX metadata, no directories/extensions. Header/path/epoch must fit USTAR exactly; do not silently switch format. Fixed zero padding/end markers and bounded writer enforce80MiB while producing bytes. Archive names are `runtime/<relative>`/`ops/<relative>`, file membership exactly the selection. StandardSHA-256 runs on actual stream bytes with per-file and cumulative caps. No application import/computation, crypto key or scientific dataset regeneration.

After close/fsync, inspect raw headers/member bytes using the frozen verifier's `verify_archive`, then write compatible `selected-source.json` with exact schema/commits/archive and per-scope per-file SHA-256/byte maps. No new manifest field is added to satisfy provenance; that would correctly fail HFIX validation. Write a separate `build-receipt.json` last after archive/manifest/selection/object evidence agrees. Receipt schema proposed `geophysics.ops-source-build/v1`, includes completed=true, source_only=true, production_activated/release_accepted/key_authority_verified=false; explicit selection digest, commits/trees, blob inventory/modes, policy version, epoch, tool provenance, archive/manifest hashes. Record observational timestamps only in receipt, outside reproducible tar/manifest. MAIN's trusted receipt review/transmitted manifest digest remains separate from bytes emitted by this builder. Building does not install/extract/activate source on Linux.

Test small real Git commits on both sides and deterministic repeated tar/manifest bytes; valid paired verifier validation after test-only installation of regular members into NEW temp source roots; no archive PAX even though `git archive` would commonly include a global header. Cover exact source-pair identity and Git blobs independently, missing/corrupt/replace/mode/link/submodule objects, missing/extra/path/case/bool/schema selection, unreviewed secret/native/raw/LFS entries, epoch/format/path limits, source count/file/total/archive bounds, process output/timeout, existing/linked/overlapping output, worktree preservation and no network/Git config/install invocation. Reuse HFIX no-Git actual-API fixture only after builder/local policy review, without changing runtime/core or relabeling it Linux evidence.

Proposed verification: focused builder tests, entire ops regression against a pinned read-only MT checkout, existing lint/content/template/CI-budget/artifact guards, scoped commit/push and self-review. Actual host remains MAIN-only and blocked at unchanged30% disk until owner decision. Environment provenance, production keys/latest deletion authority and release/admission are not builder outputs. No implementation, new test PASS, source archive or host receipt is claimed by this proposal.
