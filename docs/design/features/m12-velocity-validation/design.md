# M12 bounded learned velocity validation: design

## Scientific boundary and source basis

[OpenFWI](https://doi.org/10.48550/arXiv.2111.02926) uses multiple synthetic structural families and reports generalization studies for waveform inversion. Its [official implementation](https://github.com/lanl/OpenFWI) trains InversionNet on source-receiver waveforms and distinguishes Vel, Fault and Style families. Those data, weights and claims are not imported here. This experiment uses scalar **first-arrival travel times** for a compact, independently generated physical check. Straight-ray travel-time tomography is a linear approximation in slowness; actual refracted rays depend on velocity. The [review by Igel et al.](https://doi.org/10.1016/j.pepi.2009.10.002) describes the dependence of ray path on the model and the limits of straight-ray linearization. The present result is therefore a bounded tomographic estimate, not OpenFWI, elastic imaging, reflected-wave inversion or field validation.

## Geometry, operators and inverse crime control

The local 2D domain is 800 by 800 m with a 16 by 16 output grid of 50 m cells, `z` positive downward. Three predefined crossing-ray layouts each have 64 left-to-right and 64 top-to-bottom source-receiver pairs. Layouts A and B belong to train, validation and in-distribution control. Layout C has different source and receiver coordinates and appears only in locked acquisition tests. Each ray carries its exact endpoints and path length; no implicit fixed 16 by 16 image is treated as observed seismic data.

For slowness `s=1/v`, the inverse uses `t_piecewise = A s`, where `A[r,j]` is the exact line length of ray `r` inside cell `j`, computed from grid-boundary intersections. Synthetic picks and final forward checks instead use `t_oracle = Q s`, where `Q` integrates bilinearly interpolated cell-centre slowness along the ray with midpoint quadrature at at least eight points per cell width. `Q` and `A` are independently constructed and differ for heterogeneous models. The same `Q` is used on learned and classical predictions; neither method is evaluated with its own training operator. Gaussian pick noise has standard deviation 1 ms and is seeded per realization. The difference between a continuous/refracted physical arrival and this straight-ray oracle remains an untested modelling error.

The fixed reference is `v0(z)=2000+0.35z` m/s. All generated velocities are bounded to 1400-4000 m/s. Train and validation families are smooth layering, compact lens and dipping interface. Locked family tests are offset fault and compact high-speed salt-like inclusion, each using fresh realization seeds. These are mathematical velocity patterns, not claims of realistic sediment, fault or salt physics. No morphology is shared by simply changing an RNG seed: family labels identify different generating equations. Partition membership, seed, family, acquisition, model hash and noisy-pick hash are written to the receipt and the manifest is SHA-256 hashed.

## Learned estimator and classical comparator

The learned input has two 16 by 16 channels. Channel one is the ray adjoint backprojection of `observed - A/v0`, divided by ray coverage and converted to a dimensionless 400 m/s velocity perturbation. Channel two is normalized coverage. A three-block residual convolutional network returns `v0 + 600*tanh(output)` m/s. The map is a bounded, amortized tomographic estimate. Training minimizes mean squared model error in 400 m/s units plus 0.1 times the mean squared ray-data error in 10 ms units; the latter uses `A`, not `Q`. Adam uses learning rate 0.001, batches of 64 and a fixed maximum of 40 epochs. Minimum validation model RMSE selects one epoch; neither OOD family nor layout C changes the checkpoint. Physical scales are fixed, so there is no fitted normalization to leak.

The classical baseline solves for `q=1000(s-s0)` using `B=A/10` and `y=(t_obs-A s0)/0.01`: `min_q ||Bq-y||_2^2 + lambda ||Dq||_2^2 + 0.01||q||_2^2`, with horizontal and vertical finite-difference `D`. Cholesky solutions use the same `t_obs` and `A`; velocity is obtained from bounded slowness. The four `lambda` candidates in the requirements are selected by validation velocity RMSE only, then frozen for every test cohort. This comparator is a physics-aware regularized straight-ray inverse, not M10 FWI. Its conditioning, clipping and prior remain visible.

## Partition and verdict

The predeclared cohorts are 800 train and 160 validation realizations on training families/layouts; 160 separate in-distribution controls; 80 fault/salt family-only controls on A/B; 80 training-family acquisition-only controls on C; and 160 joint family-plus-acquisition controls on C. Their seed namespaces are disjoint. The two single-shift controls diagnose which axis contributes to a joint failure. The joint test has no training families or acquisition pairs. No split is a station/site or field survey holdout.

Per record, `RMSE_v=sqrt(mean((v_hat-v_true)^2))` in m/s. Independent oracle data RMSE is `1000 sqrt(mean((Q/v_hat - t_noisy)^2))` in ms, with noise retained because both methods see noisy data. Validation chooses a forward-residual 95th-percentile threshold. The receipt reports threshold exceedances and misses for all test cohorts. It also reports the ratio of learned to classical mean RMSE for model and oracle data. A joint held-out advantage is supported only if both ratios are below 1; otherwise the scientific verdict is failed. This does not transform shallow travel-time coverage into a unique velocity or a field-generalization statement. The source lacks waveforms, reflected arrivals, anisotropy, elastic parameters, bent rays and field labels. Checkerboard/synthetic performance cannot calibrate geological uncertainty.

## Local execution and artifacts

Run `scripts/run_m12_velocity.ps1 -Device cpu` or `bash scripts/run_m12_velocity.sh cpu` after installing `requirements-gpu.txt` or an exact-version CPU Torch 2.14.0 wheel in an ignored local environment. The command writes a compressed NumPy checkpoint and JSON receipt to an explicit local output. Its `--verify` mode reloads weights, checks SHA-256, regenerates the held-out cohorts and recomputes metrics. A short `--fixture` mode exercises determinism and shape contracts without producing acceptance evidence. Canonical `data/derived` is never rebaked by this command. A release may promote a checkpoint and compact metrics only after full local verification, code review and the separate product bake.
