# Authenticated project and raw-asset API design

## Boundary and dependencies

The API is an activated `app/` module. It has no dependency on the offline training stack. FastAPI Users 15.0.5 supplies account flows, password hashing, SQLAlchemy adapters and cookie transport. Its maintainers state that maintenance mode continues security and dependency updates; the published database strategy stores revocable tokens in our SQLite DB. The API uses that strategy rather than implementing passwords or sessions. SQLAlchemy 2.0 and Alembic own schema changes. API requirements are isolated in `requirements-api.txt`.

Library evidence: [FastAPI Users maintenance policy](https://github.com/fastapi-users/fastapi-users), [authentication backends](https://fastapi-users.github.io/fastapi-users/latest/configuration/authentication/), [cookie transport](https://fastapi-users.github.io/fastapi-users/latest/configuration/authentication/transports/cookie/), [database strategy](https://fastapi-users.github.io/fastapi-users/latest/configuration/authentication/strategies/database/), [FastAPI Users 15.0.5](https://pypi.org/project/fastapi-users/15.0.5/), and [pyproj CRS API](https://pyproj4.github.io/pyproj/stable/api/crs/index.html). The API pins a compatible tested version set; upgrades require rerunning the local security gates.

Registration, verification and reset use library routers. Verification and reset tokens are sent via configured SMTP with TLS; tokens never enter responses or logs. Password reset also revokes every database access token for that user. Missing production mail and secret configuration fails startup. The cookie is HTTP-only, Secure and SameSite Strict on HTTPS, host-only, with a 12-hour DB token lifetime. The CSRF endpoint issues a host-only token; unsafe requests require an equal `X-CSRF-Token`, an allowed same-origin `Origin` or `Referer`, and a `Sec-Fetch-Site` value other than cross-site. Test-only loopback HTTP may turn off Secure. Authentication and upload rate limits are SQLite-backed and keyed to ASGI client address; the reverse proxy must supply a trusted client address.

## Tables and transitions

Alembic revision `0001_api_foundation` creates library user and access-token tables, projects, source records, raw assets, account usage, rate windows and deletion receipts. UUIDs are opaque identifiers. Every project, source and asset query includes authenticated owner ID. Source and asset foreign keys use restrictive parent relationships; project deletion is an explicit operation, not an arbitrary cascade. A source records local-upload origin, a monotonically increasing per-project original-filename version, declared format, provider/citation, rights statement and decision, retrieval time, expected bytes, SHA-256 and attribution. A raw asset records filename, client MIME, detected format, byte count, SHA-256, storage key, immutable receipt and `raw_metadata_checked` status. No asset is marked as a validated dataset.

Upload is a raw request body with a bounded JSON `X-Asset-Metadata` header containing original filename, declared MIME/format, source and physical metadata. This avoids framework multipart spooling before the size check. The API streams request chunks to an ignored private staging directory, refusing bytes above the declared format cap (5, 20, 50 or 200 MiB) or the 200 MiB global cap. It sniffs the bytes and file envelope, compares declared MIME, validates EPSG/datum/axis-unit consistency through `pyproj` (using the official datum name or supported WGS84/NAD83 shorthand), and checks format-specific physical metadata. Archive uploads are excluded; no extraction occurs. The initial supported envelopes are gravity/magnetic/traveltime/ERT CSV, GeoTIFF, EDI, MiniSEED, StationXML, SEG-Y and MTH5. For complex binary formats the envelope check does not claim scientific parsing. A metadata-complete original is still raw and ineligible for modelling until the separate ingestion/QC adapter makes a dataset version.

After validation the API starts `BEGIN IMMEDIATE`, rechecks project ownership and the account's byte counter, inserts the source and asset, moves staged bytes to an opaque project path and commits. A failed transaction removes newly moved bytes; a startup reconciliation removes staging and export files older than one hour and unreferenced final files after the migration/head check. The DB row is not exposed until commit. The account byte counter and SQLite write lock serialize quota decisions. Private storage lies under ignored `data/raw/api/` by default and is never mounted as static content. The DB file also lives there by default.

Project export streams a ZIP containing `manifest.json` plus the exact raw members; manifest hashes, source receipts and physical metadata are sufficient for offline integrity verification. No server secret, hashed password or auth token enters it. Export fails closed if stored bytes differ from the recorded hash. Permanent project deletion records a tombstone receipt, removes DB rows and bytes, and purges API-managed backup files. External encrypted backups are an operations release contract: their restoration procedure must apply the deletion receipts before making data available; backup/restore verification is outside this API branch and blocks deployment until proven.

## HTTP surface

- `/api/auth/csrf`, `/api/auth/register`, `/api/auth/verify/*`, `/api/auth/reset-password/*`, `/api/auth/cookie/login`, `/api/auth/cookie/logout`, `/api/auth/me`.
- `GET/POST /api/projects`; `GET/PATCH/DELETE /api/projects/{id}`; `GET/POST /api/projects/{id}/assets`; `GET /api/projects/{id}/assets/{asset_id}` and `/download`; `GET /api/projects/{id}/export`.
- JSON errors use a stable `code`, `message`, and optional `fields`; 401 means no valid account, 403 means CSRF/verification, 404 hides foreign IDs, 413 means upload too large, 415 means format/MIME, 422 means metadata, 429 means rate, 507 means quota. The auth library's standard error bodies remain its own contract.
- There is no `/jobs` router or success-shaped placeholder. The separate numerical/worker unit will consume an explicitly versioned dataset contract later.
