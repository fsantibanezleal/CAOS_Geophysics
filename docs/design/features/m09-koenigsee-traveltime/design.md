# M09 Koenigsee local traveltime design

## Source, suitability and rights

The [official pyGIMLi Koenigsee example](https://www.pygimli.org/_examples_auto/2_seismics/plot_04_koenigsee/) identifies the file as classical field refraction picks and demonstrates `TravelTimeManager`, a gradient start, an on-the-fly 2D mesh and ray coverage. The existing ledger fixes the [upstream object](https://raw.githubusercontent.com/gimli-org/example-data/3bab9c6b96a606e2ca12cbdafc8c7da4f1b73c67/traveltime/koenigsee.sgt), length and SHA-256. Local re-download and acquisition matched that pin. An untruncated 58-entry fixed upstream tree has no LICENSE/LICENCE/COPYING/COPYRIGHT file; its root README supplies no raw-data grant. Therefore this vertical remains `provider-link-only`, with no committed field-derived arrays or raw mirror. The exact input has enough independent shot groups for two whole-shot predictive challenges. Its lack of source-provided errors/units remains a named limitation, not silently filled in.

## Physical contract and QC

`data-pipeline/traveltime.py` is a path-invoked script. It calls the existing ledger acquisition contract without changing the ledger or generic `ingest.py`. Its strict parser reads `<N> # shot/geophone points`, `#x y`, N positions, `<M> # measurements`, `#s g t`, then M positive picks. Sensor and shot/receiver indices are 1-based on disk and zero-based in pyGIMLi. The file has no declared CRS, local coordinate unit, vertical datum/sign, or measurement-error field. The script requires an explicit, reviewed `x/y=m, t=s` provider convention, supported by the official example's m/s starting velocities and pyGIMLi's traveltime axis; it reports this as provider-based rather than file-declared. Local y is treated as the pyGIMLi 2D vertical axis; absolute geographic elevation is not claimed. Source/receiver duplication, zero offset, nonfinite or nonpositive time and trailers fail parsing. QC flags, but does not remove or reweight, extreme apparent speeds and same-shot travel-time ordering anomalies. It records no reciprocal precision when no reciprocal pairs exist.

The local engine is fixed to one pyGIMLi thread, but this is **insufficient** to make the pinned pyGIMLi 1.6.1 inverse reproducible. An independent rerun of the prior branch changed predicted times beyond its receipt tolerance even though the physical mesh hash agreed. In direct local probes, the same saved velocity model on a freshly created mesh reproduced its original field predictions to floating-point precision. The starting gradient and fixed-model ray-coverage Jacobian also agreed across processes to floating-point precision. The first nonlinear inversion step already diverged under pyGIMLi's default inner CGLS settings (`maxCGLSIter=200`, adaptive `CGLSTolerance=-1`), and limiting pyGIMLi to one thread or setting BLAS/OpenMP thread variables alone did not fix it. The [upstream inversion step](https://github.com/gimli-org/pyGIMLi/blob/v1.6.1/core/src/inversion.cpp) calls the [CGLS solver](https://github.com/gimli-org/pyGIMLi/blob/v1.6.1/core/src/solver.cpp) for each update. Fixing `maxCGLSIter=1000` and absolute CGLS residual-squared tolerance `1e-20` yielded the same predicted-time digest in two fresh-process primary fits in the diagnostic probe; this is a numerical convergence correction, not a change selected for held-out performance.

The production method must configure and record these two inner-solver settings before fitting. Repeated fresh-process fits on the same source/code/environment must retain the same ordered cell centers and physical mesh hashes; predicted times must agree within **0.01 ms absolute, with no 2% relative allowance**, and model velocity within `0.1 m/s + 1e-4` relative per cell. The original 10%/two-of-three shot holdout and outer stopping gates do not change. Prior ignored receipts remain immutable and are never used as a warm start or overwritten. A mismatch is `unverified`, not a successful velocity interpretation. This stronger repeatability gate still does not establish unique geology or calibrated pick errors.

## Operator, oracle and inverse gate

In an isotropic speed field, first-arrival time satisfies `|grad T|=1/v` away from a source. A ray approximation integrates slowness `1/v` along a fastest path. For homogeneous `v`, the independent geometric limit is `t=||r_g-r_s||/v`; increasing `v` by two halves `t`, and swapping source/receiver leaves `t` unchanged. The numerical oracle calls pyGIMLi's Dijkstra forward engine on a distinct flat mesh with secondary nodes, not the field inverse mesh. It must agree to `1e-3` relative error. The field operator uses all surveyed x/y positions and pyGIMLi `TravelTimeManager` with fixed `secNodes=3`, `paraMaxCellSize=5`, `zWeight=0.2`, `vTop=500`, `vBottom=5000` m/s, `lam=20`, `maxIter=20`. These are the official example's parameter scale plus explicit regularization/stopping settings, not tuned against withheld picks. Errors use `sigma_t=max(0.03*t,0.0001 s)` in the same time units. The 3% part follows pyGIMLi's missing-error fallback; the 0.1 ms floor is a declared local assumption at twice the file's apparent 0.05 ms time increment. Chi-square is conditional, not instrument-calibrated.

Sort the 15 shot positions by x. Primary validation holds out shot-order indices 4, 9, 14 (zero-based; every fifth); the independent spatial-block fit holds out indices 6, 7, 8. Each trains on the other 12 shot groups, without filtering individual readings. For each training set, estimate one homogeneous slowness by weighted least squares of `t_i ≈ s * ||r_g-r_s||` using training weights only. Fit the 2D inverse, freeze the model and forward-predict all held shots through the same measured geometry without refitting. Compute absolute-time RMSE in seconds and milliseconds, signed per-pick residuals, and per-shot RMSE versus the split's own baseline. At least 10% aggregate improvement and two of three group improvements are required on both splits, along with a finite positive model and normal pyGIMLi stop before iteration 20. A 10% aggregate improvement alone is insufficient if one shot dominates. Predeclared perturbations use an alternate gradient start (`vTop=700`, `vBottom=3500`) and a finer parameter mesh (`paraMaxCellSize=2.5`) without selecting the primary model. Report actual cell counts and held-out metrics, not a preferred picture.

The manager's ray coverage is the summed Dijkstra path length per parameter cell for the training survey. Zero or small coverage is a warning about constraint support, not proof of resolution. The local receipt includes measured and predicted times, signed residuals, split indices and digests, source/code/environment/configuration/mesh digests, model and coverage vectors, engine stopping information, sensitivity runs, wall time, source rights and a SHA-256 sidecar. It is written only under ignored `data/raw/traveltime/`. A failed oracle/inverse leaves a failed local receipt and QC; the script does not create a public artifact. No waveform propagation or FWI is claimed. There are no source statics, measured uncertainty, reciprocal tests, independent site, or unique field velocity truth in this file.

## Gate sequence

1. Pin and inspect provider bytes/rights; strict parser and QC negative controls (TT-01 through TT-03).
2. Flat homogeneous analytic/Dijkstra oracle and physical unit/sign checks (TT-04).
3. Fixed source-group splits, field inverse, holdout, coverage, start/mesh sensitivity and immutable local receipt (TT-05 through TT-07).
4. Source/theory guide and per-requirement convergence verdict, with QC-only if the numerical gates fail (TT-08).
5. Independent-process inner-solver and receipt reproducibility, with a truthful failed verdict if either full-field repeat drifts (TT-09).
