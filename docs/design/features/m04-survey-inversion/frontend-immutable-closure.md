# Immutable frontend consumer closure

## Requirements

The owned magnetic result, processing consumer, course and local verification
harness shall compile against the explicitly selected existing shared shell
0.8.1 packages. The processing consumer is part of this gate, not an implicit
dependency omitted from type checking. The private loopback harness shall
declare its private visibility and the product's existing Apache-2.0 code and
CC-BY-4.0 content licenses. No shared client, controller, shell or configuration
shall be overwritten by this leaf.

## Design

Add the processing API module to the existing strict no-emit type gate and add
only the required shared-shell metadata to the owned loopback harness. Its
result still requires independently supplied verified view and receipt bytes;
no successful numerical result, authenticated mount or field claim is created.
Use the parent's existing bounded transport API rather than copying an older
shared client. A dependency-complete immutable packet lists each owned source
path and source commit, separately from shared integration prerequisites.

## Tasks and gates

1. Preserve the missing-metadata diagnostic from the existing 0.8.1 gate.
2. Check all owned frontend consumers with explicit existing packages.
3. Preserve the bounded dataset/ZIP focused test receipt independently.
4. Publish the complete source allowlist and hashes privately for parent review.

Strict type checking does not establish rendered phone height, pointer/export
routes, authenticated mounting, native execution or scientific acceptance.
