# Colocated protected consumer closure

## Requirements

The protected surveyed-input consumer shall have its actual parser, sealed
geometry planner, calibration descriptors, immutable numeric readback, view and
ZIP modules colocated with its product code. A processing client alone cannot
establish this closure. Shared authentication, controllers, worker, configuration,
bounded transport and all-writer assembly remain existing-owner responsibilities.

Every imported source shall match its reviewed immutable source bytes. Existing
public M02 exports and allocated M03 SQL model/migration are dependencies, not
permission for a private optimizer or a replacement persistence framework.
Historical loaded M03 scientific dependencies are reference-only; current owner
source and native qualification cannot be inferred from their importability.

## Design

Assemble the scoped source modules, focused tests and scientific documentation
against the explicit current-owner base. Preserve shared source files byte-for-byte.
Check every Python import without fitting or opening a native processing Job,
the frontend strict consumer type gate with the existing shared shell, and cheap
closed protocol controls. Full generation custody readback remains a separate
reserved device-lane gate. No missing module is replaced by a stub or mock.

The original final-refit allocation refusal remains a refusal. Library import,
type checks and protocol tests do not qualify the original nonzero matrix,
resource/cancellation/crash, field method, authenticated mount or deployment.

## Tasks and gates

1. Verify exact per-file bytes and preserve shared-source identities.
2. Import the closed numeric and protected API dependency inventory without fits.
3. Run bounded consumer and protocol gates with external output roots.
4. Retain all negative and first-failed-prerequisite records independently.
5. Let the existing owner mount the actual auth, quota, lifecycle and ZIP dispatch.
