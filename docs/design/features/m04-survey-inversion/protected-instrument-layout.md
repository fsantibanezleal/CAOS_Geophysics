# Protected scientific instrument: shared-owner layout proposal

This is an independent consumer review and proposal, not an applied root-layout
patch. The existing project owner retains the single shared aside, authentication,
job controls and method dispatcher. The existing shared project assembly owns
the typed shared-shell0.8.1 consumer; the magnetic leaf supplies scientific
content within that composition. No local
shell, invented CSS/font, global selector override or second method-navigation
design is introduced. No protected API route or live method is enabled here.

## One owner aside and one choice per purpose

Use the existing common method select as the only method selector. Remove
cross-method gravity/MT/profile shortcuts from individual method headers in
the owner integration; they duplicate the same choice and wrap into permanent
phone chrome. Projects/raw-data and curated-case access each appear once in
the shared owner control section, not in every scientific result heading.
Case, input/job and inspection controls are bounded sections of that ONE aside.
Split long controls by purpose instead of adding a nested scrolling rail.

Reuse the public WorkbenchLayout or CaseWorkbench owner composition, not a
second AppShell/WorkbenchShell inside the selected method. Keep at most six
question groups, one nonwrapping navigation row per active level. The M04
groups answer acquisition, susceptibility, resolution, convergence and residual
spectrum questions. Deep explanation lives in the method course/context pane;
it is not permanent prose displacing the primary drawing on every view.

Shell0.8.1 ShellConfig requires top-level bilingual license and repository
visibility. Use the actual product license and repository metadata already
declared by the product; private account/project data is NOT repository visibility.
footer.license is deprecated and does not replace the required top-level field.
Containment/fixed routes must be explicit in the reviewed parent configuration.
A dependency bump alone is not a correct typed consumer or a mobile UX gate.

## Sized native physics, not a generic picture

Use Stage/useStageSize with the actual available drawing box; PlotCard carries
lane, provenance and immutable data key. Native cell bounds, original ENU
positions and susceptibility SI/volume m3 are retained. Do not hide a large
fixed SVG letterbox inside an apparently full-width host. Physical aspect
and measured native units remain visible; a responsive transform is only a
display transform, never new cells, observations or model physics.

Original row identity/group/held-out role, measured/predicted nT and the signed
observed-minus-predicted residual share one inspection state across map/curves.
Curves preserve original order, missing predictions and acquisition gaps.
No interpolation, invented height datum, noise estimate or spectrum subset.
Resolution means the exported conditional fixed-objective free-face point
spread, not posterior geology. History presents actual saved beta/epsilon/
objective/terminal records; different objectives are not a joined convergence
curve. Native Readout/UPlot primitives may replace presentation only; they do
not change residuals, arrays, hashes, fit/selection or independent tolerances.

Physics explanation must name induced magnetization, declared background
direction, linear projection versus exact total magnitude, L2 and true-p1 IRLS,
removal of sensitivity/remanence ambiguities and sealed outer evaluation.
An unavailable derivative or field eligibility stays explicitly unavailable.
Local replay and failed/full-method/field/online gates remain distinct.
Changing physical parameters requests a NEW immutable owned configuration;
it never relabels an old generation as a new calculation.

## Binding layout floor and acceptance measurements

ADR-0071 requires the drawn instrument to occupy at least50% of the viewport
area (focus route80%), not50% of a host DIV or page scrollHeight. Its measured
stage paint floor is separately30%. The phone document-scroll exception does
not exempt the primary drawn instrument from this requirement. Pointer/touch
and keyboard reachability, native labels and complete inspection must survive.

The actual0.8.1 package stacks the rail and releases document containment below
900px. Its stacked fill PlotCard body is clamp(260px,48vh,440px). Therefore
contain:true, PlotCard fill or a package upgrade ALONE does not prove the phone
floor;48vh is already below half of viewport height before plot padding. This
is a consumer/package-owner qualification question, not permission for a local
CSS override. Coordinate through the existing shared owner composition and refer any
remaining shared primitive limitation to its owner. Do not claim the migration
fixed the screenshot without rendering the actual consumer.

Measure actual clipped drawing/paint occupancy, not just sidebar/instrument
width. Record viewport, header/footer/control and plot bounds, fit/aspect and
painted-pixel evidence. Existing width/ZIP/inspection/navigation checks stay
valuable but do not establish height or scientific UX acceptance. Test the
defined control sections open and closed, all scientific groups/subviews and
actual data keys, with no duplicate rail or permanently wrapped chrome.

Use the shared measured gate at390x844,768x1024,1280x800,1600x900 and2560x1440,
both themes and EN/ES, plus prescribed wide-font passes at390/1280. Existing
real API sixteen desktop/phone contexts are baseline, not a replacement for
these drawing/height checks. Walk real pointer/touch/keyboard navigation and
native row/cell readouts; compare exact selected generation arrays/ZIP bytes.
Loading, signed-out, failure and selection changes must clear stale science;
ready state carries the actual bound data key. No fake wait timer or fabricated
accepted fixture supplies API, resource, field or deployment acceptance.
