# Read-only single-site verification design

The approved target is one ML VPS origin, internally provisioned local accounts and a public client. This unit implements `scripts/verify_single_vps_release.py` and focused tests before the eventual qualified cutover. It does not transfer files, change DNS, retain/delete releases, migrate a live database, activate services or authenticate as the owner.

Inputs are `--origin`, the explicit completed `--build`, optional `--host-inventory` and an explicit new `--output`. Origin is HTTPS with one ordinary DNS host and no userinfo, port other than443, base path, query or fragment. Root-relative paths are generated from a validated build inventory, not remote HTML or caller URLs. Build limits are8192 files,512MiB per file and4GiB cumulative logical bytes. Stream chunks are65536 bytes; every file is rehashed after remote comparison to reject an observed local mutation. Local trusted build/parents must have no symlink/reparse components. These bounds do not claim filesystem-race protection against a malicious same-user writer.

Use standard-library HTTPS with its default certificate and hostname checks, explicit empty proxy settings, identity encoding and a redirect-denying handler. Sequential GETs have30-second socket timeouts and an1800-second overall monotonic deadline checked between chunks/requests. A blocking socket read may consume its timeout beyond that overall deadline; this is not a hard native process deadline. No retry or alternative origin. Compare remote lengths and SHA256 with each local member; stream bodies, not an unbounded read. Empty files remain legitimate. API checks use bounded4096-byte JSON: `/api/auth/config` must exactly declare local/no-registration/no-mail and `/api/projects` must return401 with a JSON body, not the SPA fallback. Index bytes must match `/`, `/introduction/`, `/methodology/`, `/implementation/`, `/experiments/` and `/benchmark/`.

An optional supplied host inventory has exact schema `geophysics.release-capacity/v1`, keys `schema`, `observed_at`, `releases`, `free_disk_bytes`, `additional_release_bytes`, `job_scratch_bytes`, `available_memory_bytes`, `worker_memory_bytes`, `api_memory_bytes`, `controller_memory_bytes`. `releases` has exactly three objects with `id`, `role` and measured `bytes`: one `current`, two `rollback`, distinct bounded portable IDs. Logical release bytes must be positive. The inventory must be no older than300 seconds and not future-dated. Disk free must cover additional release plus job scratch; available RAM must cover worker plus API plus controller reserves. Existing release/project storage is already reflected in observed free disk, not subtracted twice. This checks a supplied record, not the host: operator provenance and actual measurement remain independent requirements. No arbitrary30% rule, project backup, SMTP requirement or unrelated cleanup is introduced.

The result separates measured HTTPS/build/API observations from supplied-inventory consistency. It includes build member hashes and route counts and always sets `scientific_acceptance`, `browser_acceptance`, `worker_acceptance`, `full_release_accepted` to false. It cannot close R-017 by itself; actual scientific/UI/job/ownership/browser/retired-publication/rollback evidence must be reviewed separately. Receipt contains no credentials, user IDs, private local paths or raw host inventory. The command creates output exclusively, fsyncs it and retains any interrupted new file without claiming success. Tests use explicit supplied transports/temporary roots; those are not HTTPS or actual-host receipts.

Primary transport basis: [Python urllib.request](https://docs.python.org/3.12/library/urllib.request.html), checked2026-10-03. The existing source/build `check_single_origin.py` gate is reused, not replaced by remote availability checks.
