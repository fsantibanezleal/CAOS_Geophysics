# Maintenance backup and new-target restore design

## Scope and approval

This feature refines the approved product operations gate. Add only `scripts/ops_recovery.py`, paired launchers, `tests/ops/test_backup.py`, and new documentation. The parallel MT owner retains config/database/projects/worker. No package, service control, deployment, production restore, backup erasure or key generation command is implemented.

## Trust and consistency

An operator supplies canonical absolute paths and a short-lived maintenance JSON bound to the exact source root, database and deployment UUID. Linux mode reads systemd state for every declared writer/activation unit and requires masking/inactivity, zero service MainPID and an empty existing cgroup. The operator attests ingress is blocked and every writer (including manually launched processes, child processes and timers) is accounted for. Verify evidence and state before and after capture. A systemd observation cannot protect against a malicious administrator or undeclared writer; host permissions and the exclusive maintenance window are prerequisites. Fixture mode is explicitly marked and requires every writable/input data path inside a temporary fixture root. Fixture artifacts cannot be restored in host mode.

Reject live/nonempty WAL or rollback journals rather than copying only the SQLite main file. Open the stopped clean database read-only with immutable URI, validate the exact migration DDL fingerprint, integrity and foreign keys, then invoke SQLite's backup API into new scratch storage. No hot SQL backup is represented as a DB-plus-files transaction. Audit exact DB-referenced raw, dataset and result paths, owner relationships, content hashes and permitted derivative schemas; reject unknown bytes and nonempty interrupted directories. Observe the source again before publication.

## Recovery authority

`backup` and `checkpoint` merge the current database's durable deletion receipts into a preceding decrypted authority without losing earlier entries. Initial authority creation is an explicit bootstrap operation tied to a deployment UUID, whose history must have been independently audited. An encrypted authority has a sequence, predecessor ciphertext SHA-256, exact cumulative receipts, observation time, and cumulative snapshot records (snapshot ID/ciphertext hash/creation/expiry/policy ID). Every output is a NEW directory. The encrypted snapshot does not contain the later authority ciphertext, avoiding a circular hash. Its manifest contains snapshot identity, deployment, retention and tombstones known at capture. The new authority registers the completed encrypted snapshot's hash. A checkpoint after deletion carries registrations forward without requiring another full backup.

Restore requires explicit snapshot SHA-256 AND the independently trusted latest authority ciphertext SHA-256. Authenticated encryption does not prove freshness: the expected latest hash and the deletion checkpoint watermark must come from a separate protected/off-host operational record. Refuse a snapshot missing from the authority, expired under its declared retention, from another deployment, or whose embedded tombstones are not preserved by the authority. No automatic purge or claim of historical backup erasure. Preserve originals. Missing/rolled-back latest authority blocks recovery; never initialize a replacement authority to bypass it. Until application deletion commits are synchronously replicated outside the source failure domain, a disaster between deletion and checkpoint remains a release blocker. The guide requires checkpointing and verifying the latest current DB receipts before an actual recovery and records the pending integration explicitly.

## Archive and restore

Use age v1.3.1 or later from an explicit absolute executable path, x25519 recipient only and a restricted existing native identity file for decryption; no passwords, plugins or custom crypto. A plaintext uncompressed USTAR archive is generated only in restricted temporary scratch. Decryption streams to a byte-limited file with timeout and discarded diagnostics. Manifest precedes ordinary file members; reject duplicates, directories, links, noncanonical paths, unknown names, PAX/sparse metadata and count/size/hash drift. Extract manually with exclusive file creation into NEW temporary scratch, never `extractall`. Validate all member hashes before database mutation. Retain failed owned scratch as restricted diagnostic quarantine only if normal temporary cleanup cannot complete; never remove user-owned input.

Reconcile tombstones in scratch: explicit child-table deletion in FK order; preserve/insert receipts only for users known to the snapshot, retain every receipt including newer unknown owners in the external authority; exact recorded file unlink only; revoke access tokens and rate windows; rebuild raw-byte quota; `VACUUM` the new DB to remove deleted content in freelist pages; validate integrity/inventory again. A new target contains `private/api.sqlite3`, immutable survivors, encrypted latest `authority.age`, and `receipt.json`. Publish into an exclusively created target with a success receipt written last; incomplete targets have no validation receipt and cannot be used. The tooling never activates that directory as a production root.

## Limits and validation

Explicit maximum file count, total plaintext bytes and per-file bytes are applied before allocation/copy/extraction. JSON and tombstone payloads have separate caps. New directories are 0700 and files 0600 on POSIX. Windows fixture confidentiality relies on inherited private temp ACLs; production Windows mode is rejected. Symlinks, Windows reparse points, multi-link regular files and overlapping roots are rejected; trusted parents cannot be writable by adversaries. A golden DDL fingerprint pins `0003_processing_jobs`; changes by the MT owner need a separately reviewed adapter and tests rather than accepting unknown future revisions.

Real age, real migrated SQLite, adversarial archives and real API deletion are exercised locally using temporary fixtures. Systemd behavior is tested with controlled state responses; the actual host is a separate main-agent gate. No scientific training/bake or CI change is part of this unit.

Host-unit handoff: `run_one` recovery marks abandoned running jobs failed but reconciliation rejects preserved `.job-staging`. Backup capture also rejects that state. The host unit tests refusal, quarantines only its exact harness stage outside the private root and reruns. This is operator-assisted crash recovery, not an unattended recovery guarantee. Actual-host execution remains a separate bounded user-owned private `StateDirectory` drill after review.
