# Bounded source intake design

The inspected primary references and exact access/correction findings are in [the source dossier](../../../research/bartlett-source-review-2026-10-03.md). Direct ScienceBase attachment access fails; its public FGDC XML is available. The related author archive contains actual principal-fact CSV channels in a transformed/compiled study dataset. It must not be renamed byte-identical USGS raw data. The original source/datum lineage still needs independent review for field inversion.

Extend the existing reviewed local ledger/acquisition engine with two explicit formats: FGDC metadata XML and research ZIP. Both remain byte/hash-pinned; allowlisting exactly the two public provider hosts does not authorize arbitrary URLs. ZIP intake checks the entire inventory for entry count, expanded bytes, per-member size, expansion ratio, path canonicality, duplicates, symlinks and encryption before selection. Only exact declared CSV/PDF members may be extracted, each with a frozen size/hash. No third-party code, pickle or model is executed. Bytes are staged, verified and installed with exclusive hard-link semantics under ignored local data. Existing matching files are reused; disagreement is preserved and reported. A source-bound receipt names each selected object and its permitted use.

Principal-fact profiling is not M01 correction or M02 inversion. The strict UTF-8 CSV reader requires the exact author header, preserves all OG/FAA/SBA/TTC/CBA/ISO channels and reads numeric finite values without unit guessing. It records station IDs, declared WGS84/UTM10N horizontal coordinate channels, source height label, explicit unresolved vertical datum and absent measurement uncertainty. No masks silently turn into zeros and no outlier is excluded. Finite/missingness, duplicate station/coordinate and physical range diagnostics remain visible. The result has no predicted/model/truth keys and does not claim method eligibility. A future physical transform creates a new derivative; it never corrects a provider anomaly twice.

The author archive and selected source objects stay ignored; only compact source/provenance/profile evidence with rights/attribution may be committed after validation. The downloader and profile commands are local and paired PowerShell/shell entrypoints; product CI may validate only committed metadata, never fetch or profile external data. Tests use small original fixtures with the same schema and deliberate malformed inventories. An opt-in real-data test requires the actual pinned archive and checks its bytes and profile, skipping honestly when absent.

## Completion refinements

Ledger validation is shared with direct extraction callers. Contracts use exact known keys, positive finite bounds, lowercase SHA-256 pins and CSV/PDF-only selections. Independent ceilings (512 entries, 500000000 expanded bytes, 200000000 per member, ratio 1000) prevent a malformed contract from authorizing unbounded expansion; this source has narrower 64/350000000/200000000/1000 limits. Names are portable canonical ASCII and reject Windows devices, dot/space aliases, case collisions and file/parent collisions. Storage rejects Windows junction/reparse points as well as symlinks. Both selected-object and receipt disagreements are checked before normal publication; complete receipt bytes are staged and exclusively hard-linked. A second archive digest before installation detects concurrent byte changes. Multi-file installation is not transactionally atomic across OS failures; identical retry is safe, disputed objects are never replaced.

The profile retains original index tokens and CSV line ends, verifies real-source member pins and rechecks its input digest after reading. Diagnostic ranges never clip, replace or exclude observations. Processing attribution is expressly not independent station-level lineage verification. No correction, sign reversal, elevation interpolation, error weighting, original-USGS byte-equivalence claim or canonical-case publication is introduced.

The completed actual inspection and ignored receipt/profile file hashes are in [compact evidence](../../../research/potential-source-intake-evidence-2026-10-03.json); the repeatable commands and method non-claims are in [guide 11](../../../guides/11_potential_source_intake.md). The validation/handoff record is maintained separately from those measured counts.
