# Design: one private EDI screen and inverse vertical

## Boundary and contracts

The existing authenticated upload stores the original EDI outside the web root. `POST /datasets` creates an immutable EDI envelope dataset from its owner-scoped raw receipt. It does not call a solver or assert 1D eligibility. Its metadata binds the station ID, count, all four impedance tensor components, declared impedance unit, time sign, variance convention, common rotation and frame. M05 is a separate queued worker job with no scientific tuning parameter. Its child reads the exact raw asset path after both parent and child verify byte count and SHA-256, then calls `screen_edi`. The screen is retained as a versioned job result, including the full tensor and tipper diagnostics. A malformed source fails the M05 job, retaining a non-success receipt.

M06 admission requires a successful M05 job for the same dataset and exact raw hash, with `one_d_inversion_eligible=true`. This is a necessary tensor consistency screen, never proof of 1D geology. M06 reads the original EDI again, calls `invert_edi`, and independently checks its full tensor screen. Clear Lake cl061 fails this gate; no parameter or frequency selection can bypass it. User-submitted finite-layer thicknesses are imposed, not estimated. Limit to a halfspace or two layers and bounded TRF only. The user supplies the starting resistivities and beta; the service uses a fixed every-fifth-frequency holdout chosen before the fit. The child records all starts, a training-only halfspace comparator, one declared beta alternative and two thickness perturbations for the two-layer case. It reports selected fit plus failed/successful alternatives; no field truth score.

Original EDI units are `ohm` or `(mV/km)/nT`, converted by the existing parser to E/H ohm. Negative-time conventions are conjugated to `exp(+i omega t)`. The parser divides complex variance by two for marginal real/imaginary SD and preserves per-real variance. Common tensor rotations are preserved; geographic rerotation is allowed only for an exact 90-degree signed permutation with an explicit north reference. EDI tipper is QC-only. Bootstrap intervals, if requested, are pointwise conditional on fixed layer count/thickness, independent Gaussian marginal error, beta, bounds and source frame; they exclude dimensionality, correlated noise, static shift and geological uncertainty.

The existing generic processing tables and migration remain sufficient: the method, immutable request, dataset SHA, preflight and result receipt are already typed. Dataset and result JSON validators branch on modality/method. The worker keeps the singleton lock, child-process watcher, cancellation and crash recovery. The EDI child has a fixed command, a stripped environment, a parent-death watch and OS/parent resource controls. It imports `data-pipeline/edi.py` and its SciPy TRF engine directly; no second parser or inverse is introduced. A separate MT bundle validator extends the existing ZIP contract while leaving gravity serialization untouched.

The 2026-10-03 security review adds an admission check in the storage-only worker configuration, so a queued job cannot continue after the worker's MT gate is closed. Numerical-library thread counts are fixed to one inside the stripped child environment. After source hash/count verification, the child writes the exact verified bytes once to private `source.edi` staging and all parser/inverse calls read that snapshot. The public original is never rewritten; the snapshot's bytes count toward admission estimates and measured scratch, and successful/failing staging cleanup recognizes only exact known files. This also makes repeated M05/M06 source-file provenance stable without a new source or unmeasured truth. Re-import checks declared units, sign, variance and frame against the serialized parser receipt, in addition to numerical array/hash checks.

## Local numerical and host admission

The independent halfspace oracle uses analytic `Z=(1+i)*sqrt(pi*f*mu0*rho)` from an original synthetic EDI source, with exact raw hash and no target passed into the inverse. A noisy two-layer fixture demonstrates nontrivial beta and thickness response and held-out prediction. Negative controls mutate required blocks and source metadata and use cl061's recorded failed full-tensor screen. API gates exercise wrong owner, raw drift, bundle tamper, queued/running cancel, timeout, memory, scratch and recovery. Nominal/upper/malformed wall/RSS/scratch receipts are collected locally. Production admission is an explicit default-off setting until the same matrix plus 30% headroom and cancel/crash recovery is measured on the actual ML VPS. No deployment is in this change.

The upper local matrix must cover the admitted byte boundary as well as numerical dimension: a 5 MiB original with 512 frequencies for M05, and a 5 MiB original with 64 frequencies and 40 bootstrap members for M06. EDI comment padding changes byte/scratch load without inventing extra scientific observations. A 512-frequency M05 receipt cannot authorize M06 beyond its 64-frequency cap. Result re-import recomputes interval summaries from the exported ensemble; this checks serialization consistency, not field coverage.

The reviewed runtime pins NumPy, SciPy, MT Metadata, pandas, matplotlib and xarray without Torch. Each result/export records actual Python/package versions and their canonical digest alongside scientific code hashes. Offline all-solver tests use their separate Torch-capable environment. Preserved static release artifacts remain subject to their strict source-fingerprint guard; the online change does not relabel those older receipts as new executions.
