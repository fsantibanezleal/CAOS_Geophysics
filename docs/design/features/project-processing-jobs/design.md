# Bounded project processing and CPU worker design

## Evidence and boundary

The approved product SDD separates immutable raw originals, validated datasets, processing runs, solver jobs and result artifacts. The merged local ingestion dispatcher accepts reviewed SimPEG observation archives and Clear Lake EDI, with EDI QC-only; `read_csv` in that module accepts exactly `east_m,north_m,up_m,value,sigma` for a separate local inversion CLI. Neither is an authenticated project dataset adapter. The existing API `gravity_csv` upload validates only envelope and declared metadata, not all rows. This unit adds a deliberately narrower API-owned gravity table contract, not a claim that the offline adapter or M01 gravity correction chain is complete.

## Typed dataset and processing method

`POST /api/projects/{project_id}/datasets` accepts only `{asset_id}`. It re-hashes the owned raw original and requires `gravity_csv`, EPSG projected xy coordinates in metres, vertical metres, mGal values and an explicit `sigma_column` in the raw asset's geometry metadata. The CSV must have precisely the six declared station/x/y/z/value/sigma columns, 4-4096 rows and at most 2 MiB. Station IDs and XYZ triples are unique, numbers finite, and sigma is strictly positive in mGal. No unit conversion, CRS inference, missing-value replacement or exclusion occurs. The immutable `observation-dataset/v1` JSON carries station axis, IDs, original values, uncertainty, all-false mask, no missing reasons, physical metadata, source rights, raw hash, parser version and empty correction history. Its canonical UTF-8 bytes and SHA-256 live under private `derived/<owner>/<project>/datasets/`. API paths are generated from IDs only.

The only activated method is `gravity.station-outlier-flags/v1`, explicitly a processing-only M01 precursor. Given `threshold` in [1, 10], it computes median and scaled median absolute deviation of the observed mGal values and flags rows whose absolute deviation exceeds `threshold * 1.4826 * MAD`. A zero MAD yields a typed degenerate-scale rejection, never an invented uncertainty. Input observations and sigma remain unchanged. The result records scores, flag mask, statistic, threshold, source/dataset hashes, code hash, rights and a no-exclusion statement. It emits no model, prediction or inverse residual. An independent five-station hand control tests the expected mask and parameter effect.

## Durable state and admission

Alembic adds `observation_datasets` and `processing_jobs` with owner/project foreign keys and immutable request/input identity. Dataset and result JSON are private, hashed, read-verified and included in startup inventory. Job states are queued, running, succeeded, failed or cancelled; cancellation of a running job is a durable flag until the worker terminates the child. A fresh retry is a new job ID, never an overwrite. The submit path uses `BEGIN IMMEDIATE` to recheck ownership, method/dataset eligibility, one active job per account and a bounded queue. It records a canonical request hash, dataset hash, method/version, preflight estimate and explicit limits. No API background task executes the method.

A separate `python -m app.worker` process takes a single-worker file lock, marks abandoned running jobs failed on restart, claims one queued job transactionally and launches `python -m app.compute` with a fixed argument vector, restricted environment, fixed working directory and no shell. The worker watches cancellation, wall time, process-tree RSS and scratch size, terminating the process tree and recording a non-success error on breach. The fixed child applies POSIX `RLIMIT_AS`/file-size limits before reading data and watches a dedicated parent pipe so a crashed worker closes the pipe and stops the child on both supported local platforms. The child writes only a bounded staged result; the worker validates and hashes it before atomic installation and success commit. Unknown staged bytes or uncertain commits are preserved for startup operator recovery, never age-swept.

The provisional product ceilings (one worker, one active/account, 2 GiB memory, 1 GiB scratch, 10 minutes) are upper safety bounds, not method benchmarks. This small flag-only method has tighter 256 MiB RSS, 8 MiB scratch and 30-second wall caps. Account storage admission combines the raw-byte counter, stored derivatives and an 8 MiB active-result reservation against the 1 GiB private-byte quota. [psutil 7.2.2](https://pypi.org/project/psutil/7.2.2/) is pinned for cross-platform process-tree RSS/termination; its [official process API](https://psutil.readthedocs.io/stable/) informed the monitor. A host-specific nominal/upper/malformed benchmark and unprivileged worker service configuration remain release gates.

## Lifecycle and export

GET endpoints list/read owner datasets, method verdicts and job status/result. POST cancel handles queued and running jobs; completed jobs cannot be rewritten. `GET .../export` produces a manifest plus exact dataset/result JSON bytes. The manifest includes schemas, hashes, rights, units and provenance but no raw original or storage key. A strict local verifier rejects tampered members and schema/identity drift. Project DELETE refuses active jobs or unverified derived bytes, records a derived manifest in its durable deletion receipt, and removes only those exact owned files after commit. A crash preserves `.deleting` bytes and blocks startup; backup erasure remains unclaimed and operator-owned per R-API-09.

Security: all project/dataset/job queries include the authenticated owner. User JSON cannot select a filesystem path, command, interpreter, environment or method implementation. Source rights remain owner-only in this unit, including `mirror`. No public raw or derived publication occurs.
