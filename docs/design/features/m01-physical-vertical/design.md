## 2. Lanes and causal flow

```text
existing authenticated project and permitted private original upload
  -> strict bounded structural JSON root (no scientific solve)
  -> server-bound immutable parent/config job request and reservations
  -> existing single worker, one fixed physical compute child
  -> real ordinary correction OR distinct real transform and its admission
  -> exact private publication intent and completed files
  -> one DB commit exposes child + edge + producing job + result
  -> selected-project App plots/readouts and private graph export
```

Raw bytes stay unchanged in existing private storage. The API root is structurally checked but not certified as physically correct. A successful correction verifies its scientific history/values inside the child. A transform consumes a successful correction's entire result/error receipt, not just a vector of anomalies. Curated local controls are labelled synthetic; loaded stored results are replay, while a submitted job is real new computation. Offline recipes remain available for overbounds or closed admission, without substituting saved output for a run.

The API performs byte limits, strict types, structural bounds, ownership, digest checking, quota/queue transactions and exact typed serialization only. No Boule, Harmonica, NumPy, SciPy, Verde, projection engine, process_survey, transform_survey, covariance eigensolver or physics verifier is imported/executed by this lane in request/background processes. Scientific geometry/covariance/history validation is child work. Existing MT/flag behavior is unchanged; this requirement is not a claim that legacy bundle verification already has that separation.

## 3. Immutable dataset-version DAG

Extend the persisted dataset schema explicitly; do not hide derivations in parser_version. Proposed fields are kind (`root`/`derived`), root_dataset_id, parent_dataset_id, payload_schema and lineage ordinal, alongside existing id/owner/project/raw/parser/hash/bytes/storage/created identity. Existing `version` becomes the explicit root-family ordinal. Preserve all old rows as root, ordinal 1, root_dataset_id=id, parent=null, old payload_schema=v1, without rewriting old bytes or responses.

Replace global UniqueConstraint(raw_asset_id,parser_version) with named UNIQUE(raw_asset_id,parser_version) WHERE kind='root'. Retain parser_version as the root parser identity for all its children. Add UNIQUE(root_dataset_id,version), CHECK(version >= 1), root/parent-kind nullability checks and composite unique identity for owner/project/raw foreign-key links. Root IDs and parent IDs must resolve within the same owner/project/raw family. A separately persisted production relation links a child to one producing job and result identity without a dataset/job FK cycle. No unknown modality or future method acquires permission by sharing a raw ID.

Current methods admit exactly one immutable scientific input parent. Therefore the initial stored DAG is a branching forest, not an arbitrary multi-parent computation claim. Each child has exactly one edge, its parent's ordinal is lower, and an existing node can never receive a new parent or rewritten scientific metadata. Cross-row root-kind, edge agreement, monotonic ordering, payload/receipt relationships and acyclicity are checked transactionally and by full startup/recovery audits, not claimed as consequences of a simple CHECK or ORM relationship. Future multi-input methods require a reviewed schema/role adapter.

A root-family sequence record allocates ordinals under BEGIN IMMEDIATE when a publication intent is reserved, not from parent.version+1. A failed intent leaves a gap; ordinal is identity, not correction count, history length, completeness or scientific stage. Retrying is a new job/child UUID and ordinal, never an overwrite. Limits: at most 64 published-plus-reserved nodes per root family, maximum current input ancestry depth four edges (root, up to three later correction states, terminal transform). Siblings are allowed. New corrections on an earlier node form a branch; identical same-parent/method/exact-submitted-parameters requests use the existing active/successful identity as specified in contracts. Existing old roots are not deleted to meet these limits.

All successful versions are immutable; no endpoint edits a parent, changes source statements or removes an individual ancestor. Project deletion remains the lifecycle boundary. A newly uploaded already-corrected gravity-stations-1 history is a declared root whose history is scientifically checked in the child; it is not an invented API ancestor graph or an authenticated old processing receipt. Transform admission requires a produced correction child and its successful job.

## 4. Ordinary correction and separate transform

Correction ID `gravity.station-corrections/v1` consumes exactly Curie's reviewed six-key adapter request. Wrapper identity never enters gravity-stations-1 or its config. Its four-key output and 13-key receipt remain unchanged, including host_approved/full_method_accepted/field_source_verified=false. Main's distinct execution admission receipt may authorize a job but cannot flip the function's non-certification fields.

The core produces correction additions, propagated errors and retained outlier diagnostics, no model prediction/residual. Strict same/earlier stage or changed prior history/config rejects. Primitive zero SD remains legitimate where declared; null/missing SD is never zero. A terrain residual is supplied explicitly with its source/density/height/station/error contract, not a computed terrain service. Flags do not silently exclude stations.

Proposed separate online ID `gravity.equivalent-source-transform/v1` maps to the existing unchanged gravity-transform-request-1 / gravity-transform-result-1 scientific contracts. Its method ID and wrapper must receive main's review; it is not an existing online method. The request includes the entire actual correction_result from the selected correction child, supplied metric geometry/mask/reasons and transform config. Bind its correction parent's producing job, adapter result and core receipt to exact stored bytes. API checks shape/types/exact keys only; child performs replay, original-height comparisons, covariance PSD, rank/extent/precision checks, split and fitting. It calls transform_survey once; that function's correction replay is included in the same CPU budget and emits no second corrected version.

Do not mutate the local transform's existing reconstructed-earlier-parent restriction to make a valid integer-parent correction pass. Its actual rejection remains visible. Supporting an exact-parent scientific replay variant would require a separately reviewed core/adapter amendment with its own version and tests. The graph already preserves the exact evidence needed for such a review; storage must not fabricate canonical earlier floats.

Successful transform execution can return selection.status=unmet_height_precision and height=null. Persist that complete diagnostic result and child as execution-success with scientific verdict `non_pass`, ineligible for further physical computation; never claim selected continuation passed or throw away failed candidates. Engine/contract/resource/partial-output failures remain job failed with no published child/result. All unsupported grid/station predictions retain JSON nulls and coverage reasons. Coefficients/source-plane depths are mathematical equivalent sources, not density, mass or geology. Conditional covariance propagation excludes geometry/parameter-selection/bias/geological uncertainty and uses diagonal fit weights, not GLS.

## 5. Worker and resource envelope

Use the existing file-locked single worker and private staging. Dispatch only exact reviewed method/schema/module identities; no prefix fallback, arbitrary command/path/import/provider URL/pickle. Minimal child environment, one BLAS/OpenMP/Numba thread, bounded fixed cache within the accounted stage, stdout/stderr cap, parent-stdin loss termination, full process-tree kill/reap and no detached descendants. No pip install or runtime upgrade follows from a job. Trusted module hashes include wrapper, adapter, scientific core and, for transform, transform module plus dependency/runtime manifest. Recheck actual imported file identity before numerics. Module hashes are integrity controls, not package-origin authentication.

Proposed hard ceilings for review, not measured admission:

| Lane | Tree CPU time | Wall | Aggregate RSS | Private scratch | Result/envelope |
| --- | ---: | ---: | ---: | ---: | ---: |
| Correction | 60 s | 120 s | 768 MiB | 256 MiB | 64 MiB |
| Transform | 240 s | 300 s | 1536 MiB | 512 MiB | 64 MiB |

Ceilings fit within existing global 2-GiB worker memory/1-GiB scratch/600-s wall limits but are not estimates proven sufficient. Aggregate CPU is real user+system CPU of child and any descendants, including exited descendants, imports, JIT and replay; parent hashing/serialization is separately bounded. Linux accounting must prove it can retain exited-child CPU or reject the lane, not sample only the currently living root. Wall is not a CPU receipt. An OS hard limit and parent monitored accounting are complementary. Windows QA needs its own measured enforcement behavior, not a Linux claim. Cold/warm runtime and worst legitimate geometry/covariance/candidate/grid controls must pass without shrinking data or relaxing physics. Otherwise remain blocked or revise these proposed limits through review within approved global capacity.

Reserve queue capacity, permanent child/result ceiling and scratch before launching. Root/raw reads are bounded and identity-verified. Final child outputs must be ordinary exclusively created files with expected names/schema/size/hash, complete success marker and no unknown links/extra files; no path supplied by a user becomes an execution path. Worker parent may wrap structurally checked child output in owned application envelopes and hash it, but never rerun a solver/verifier to certify publication. Independent physics checks run in explicit local numerical gates, not hidden request-time work.

## 6. Publication, quota and cancellation

Publication is atomic DB visibility, not an atomic transaction spanning filesystem and SQLite. See [migration/recovery](migration-recovery.md) for the exact state/crash matrix. A durable intent reserves child UUID/ordinal, fixed expected target names, bytes/hashes, job/parent/raw/request/module/config/receipt identities and pending-byte liabilities. Stage files are fsynced and verified before exclusive installation; directories are synchronized where the platform supports the reviewed guarantee. Receipt/intent digests do not hash themselves.

Final BEGIN IMMEDIATE checks ownership, running job, cancel flag, unmodified parent/raw/request/pins, exact installed bytes, reserved quota and method admission. One commit inserts child/edge/production relation, sets successful result metadata/job/resources and consumes the intent reservation. Public dataset/job/export queries expose only that complete committed relation. Cancellation committing before final publication wins and publishes no child. A success commit before cancellation yields terminal 409 on cancellation. Network loss never invents either outcome. Files left by interruption or uncertain commit are retained, not adopted, swept or called successful.

Quota equals unique stored raw bytes plus all committed dataset/result bytes plus unconsumed permanent/scratch reservations and pending orphan/deletion liabilities. Parents are charged once as files, not recursively for each child; if a result embeds a duplicate physical object it is actual additional stored bytes and is charged. Existing AccountUsage.raw_bytes remains raw-only; graph-derived totals and liabilities have explicit typed accounting. Admission serializes per-account checks and existing one-active-job/max-32 queue policy. Unknown method has no flag-method reservation fallback. Failure releases reservations only after exact known cleanup proves no remaining charged bytes; unknowns block further admission/startup and retain liability. Root installation also uses the reviewed intent boundary, not today's unjournaled root write promoted as crash-safe.

## 7. Owned API, bundle and recovery

Reuse existing authentication/session/CSRF/rate-limit/source attestation and project/raw/dataset/jobs/result/export operations. No invented auth/SMTP/provider. Owner-scoped relationships return 404 before exposing existence. Structural rejection reports bounded fixed code/field/reason, never private values/citations/paths/tracebacks. Stored future variants require exact schemas; no generic gravity fallback. Discovery exposes separate structural eligibility, scientific-verification status, adapter/pin compatibility, resource and reviewed execution-admission reasons, without pretending a queued job is a scientific pass.

The physical v2 bundle carries a topologically ordered bounded ancestor graph, producing requests/results/receipts needed for each ancestor, latest result, masks/units/axes/errors/modules/config hashes and existing source/rights statements. Raw bytes are excluded; owner-only raw project export remains separate and unchanged. No scientific solve runs on export/re-import HTTP calls. See contracts for member layout, limits and integrity semantics. A verified hash roundtrip is not an independent numerical oracle. Re-import never dispatches code or makes a new root appear authenticated; an imported graph remains a verified private artifact unless an explicitly reviewed future persistence operation is authorized.

Project deletion blocks active jobs/intents, verifies the complete graph/inventory, moves exact owned files under the existing deletion staging boundary, commits tombstone and all relation/row/quota changes together, then purges only exact recorded files. No recursive orphan sweep. Pending cleanup debt remains reserved and recovery-blocking. Backup erasure stays not_attempted/external reconciliation pending. Existing synchronous off-host tombstone durability gap remains an independent main-owned release blocker; no new deletion provider is selected here.

Future migration changes invalidate the old recovery adapter's exact revision/DDL contract. New explicit adapters must preserve old 0003 roots/gravity/MT, new physical schemas/graph/production/intents and latest authority. Old tooling rejects the new revision; changed DDL under the old label also rejects. Backup refuses outstanding stages/intents/liabilities. Restore remains new-target-only, maintenance-bound for capture, trusted latest-authority-bound for deletion reconciliation, session-revoking and fail-closed on unknown variants. No production restore/host drill is claimed.

## 8. Scientific App instrument

Integrate a distinct physical gravity mode into the existing selected-project workbench, with at most six grouped sections and the shared shell's fonts/tokens/theme/language/equation/citation primitives. No extra top-level route or standalone app. The primary linked instrument uses at least half the App viewport, with one owned scroll container and phone controls actually reachable by pointer/keyboard. Retain gravity flags and MT instruments without sending physical payloads into their parsers.

Data controls select raw/root/version/job by immutable identity, display parent branches and actual receipt/state, upload only supplied physical JSON and expose validation versus scientific job outcome. Corrections offer actual target/error model/density/density SD/outlier threshold and supplied terrain config with conditional availability. Submitted config stays frozen beside editable next-job controls. Changing density and submitting creates a new physical result branch, not a view-only redraw. Transform controls accept actual declared metric mapping/masks, candidates, heights, bounds/spacing/coverage, blocked seed/folds and error/covariance contract. They never generate a projection, geoid or covariance from missing inputs.

Correction panels: lon/lat axes in degrees (not metric equal-aspect distance), station original in declared units/sign and converted original_mgal, current disturbance mGal, exact additive terms, receiver/surface ellipsoidal m, history hashes, QC score dimensionless/null and flags, all stations, primitive and propagated uncertainty components with SD versus bound captions. Difference current-minus-converted-original is a labelled correction sum, not observed-minus-predicted residual. No predicted curve/model/heldout score for corrections.

Transform panels: equal-aspect easting/northing m maps and declared height m, covered/null grids mGal, conditional error mGal, station observed/predicted and **predicted minus observed** signed residual mGal and dimensionless normalized residual, distinct train/holdout/masked marks, covered/unsupported denominators, candidate CV/condition failures, frozen split hash, height/precision comparisons, nonunique coefficients mGal m and source coordinates m. Explicitly show unmet-height-precision/null selected height. Sequential colour for magnitudes; zero-centred diverging signed residual; missing values are holes/reasons, not zero. No toy 3D property volume or geological layer model.

Pan/zoom/region/reset/station selection/height/grid quantity/table-export controls change a labelled view or actual submitted calculation. Unit/axis mapping and linked readouts update from the same result ID. Changing owner/project/version/method/job/session aborts pending requests and clears private results/selections; stale polling cannot refill them. Expired session, ownership404, network failure, cancellation, timeout, safe contract/runtime errors and closed admission have literal EN/ES states. Screenshots must use actual completed jobs and real pointer parameter effects/export, not fixtures posing as live results. Future course/wiki content changes belong to separately assigned owners and are not authored by this design branch.
