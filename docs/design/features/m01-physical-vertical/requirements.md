# M01 physical dataset-version vertical requirements

Status: planned. Date: 2026-10-03. Full main review is required before any product code. All gates below are prospective, unimplemented acceptance specifications. Existing ordinary/local scientific tests are dependencies, not proof these gates have run. Read [research](../../../research/m01-physical-vertical-2026-10-03.md), then [design](design.md), [contracts](contracts.md), [migration/recovery](migration-recovery.md), [validation plan](validation-plan.md) and [tasks](tasks.md).

Parent: approved product SDD R-002..R-007, R-009, R-011..R-016 and R-018. Scope: exact uploaded physical JSON, real bounded correction and distinct transform children, owned immutable graph/API/export and selected-project App. Excludes provider acquisition, new host/auth/mail/deletion providers, generic CSV conversion, inverse geology, production admission or release. No existing frontend or shared source is edited by this documentation unit.

R-MPV01 WHEN an authenticated owner uploads gravity_stations_json, THE platform SHALL preserve exact original bytes/source permission/rights and separately validate only the bounded exact physical contract without guessing metadata or relabelling flag CSV. Gate: tests/api/test_m01_physical_upload.py::test_private_exact_json_original_and_no_csv_conversion.

R-MPV02 BEFORE creating a physical object or queue request, THE platform SHALL reject duplicate decoded keys, malformed UTF-8, unknown fields, boolean numeric values, nonfinite constants/overflow, excessive tokens/depth/nodes/strings/bytes and invalid declared types, without scientific imports or calculations. Gate: tests/api/test_m01_physical_upload.py::test_strict_bounded_decode_before_science.

R-MPV03 WHEN a root or child is persisted, THE platform SHALL use explicit immutable root/parent/version/production identities, root-only raw/parser uniqueness and same-owner/project/raw edges, preserving every legacy root ID/version/parser/payload/hash/job reference. Gate: tests/api/test_m01_dataset_versions.py::test_root_uniqueness_branch_versions_and_legacy_preservation and tests/api/test_m01_migration.py::test_0003_roots_jobs_bytes_unchanged.

R-MPV04 WHEN a correction executes, THE fixed child SHALL consume Curie's exact six-key request and return the exact four-key result/13-key receipt through the reviewed adapter, binding exact parent and submitted/normalized configs while retaining original values/history/errors/QC/non-certification declarations. Gate: tests/api/test_m01_child.py::test_real_adapter_exact_parent_and_receipt_parity.

R-MPV05 WHEN a transform is requested, THE platform SHALL bind a successful physical correction parent and its producing receipt plus separately declared geometry/config to a distinct request/result/method, execute actual transform_survey inside the same bounded child, and retain frozen splits/coverage/conditional errors/non-pass precision diagnostics without emitted re-correction or invented density. Gate: tests/api/test_m01_child.py::test_distinct_transform_and_exact_correction_parent.

R-MPV06 THE API and worker publication parent SHALL perform only bounded structural/identity/integrity operations for this lane, with every correction replay, projection-related scientific admission, covariance factorization, fit, propagation or independent numerical verifier confined to one fixed monitored scientific child or a separately explicit offline gate. Gate: tests/api/test_m01_child.py::test_request_parent_zero_science_and_single_child.

R-MPV07 WHILE a physical job is active, THE worker SHALL enforce one aggregate process-tree CPU budget, wall/RSS/scratch/output ceilings and fixed trusted modules/pins/environment, terminate descendants on cancellation/parent loss/overrun, and record measured non-success without a published partial child. Gate: tests/api/test_m01_limits.py::test_real_cpu_wall_rss_scratch_cancel_and_parent_loss.

R-MPV08 WHEN publication is attempted, THE platform SHALL bind exact raw/parent/request/module/config/receipt/output identities in a durable intent and atomically expose the child, edge, production relation, result and successful job through one DB commit, preserving uncertain files and reservations until reviewed reconciliation. Gate: tests/api/test_m01_publication.py::test_every_crash_cut_and_cancel_linearization.

R-MPV09 WHEN upload/submission/publication/deletion account for private storage, THE platform SHALL charge unique stored raw/dataset/result bytes and live reservations exactly once per stored file, serialize admission, retain orphan liabilities and prevent quota bypass by branching, retry, pending deletion or unknown methods. Gate: tests/api/test_m01_publication.py::test_quota_reservations_graph_and_orphan_liability.

R-MPV10 WHEN any project, raw, parent, producing receipt, job, result, graph or export identity belongs to another account or project, THE API SHALL return indistinguishable ownership-scoped 404 without leaking existence, paths or scientific values. Gate: tests/api/test_m01_ownership.py::test_owner_project_parent_receipt_404_matrix.

R-MPV11 WHEN a successful physical job is exported, THE bundle SHALL preserve its bounded transitive ancestor graph, exact request/scientific result/adapter receipt/modules/configs/axes/units/masks/errors/rights and typed scientific verdict with verified member bytes/hashes, without embedding raw files or executing numerics in the request; browser verification SHALL start unset/closed and require bounded source-byte scan/typed parsing and measured per-device maximum live memory admission, never a512-MiB phone assumption or weaker legacy guard. Gate: tests/api/test_m01_bundle.py::test_graph_roundtrip_tamper_caps_and_no_request_numerics plus frontend/e2e/m01-physical-live.spec.ts::bounded_source_bytes_and_device_memory_admission.

R-MPV12 WHEN a terminal owned project is deleted, THE platform SHALL include every root/child/result and graph relation in the existing exact tombstone and deletion transaction, preserve survivors, and retain pending physical cleanup liabilities without claiming backup erasure or inventing a deletion provider. Gate: tests/api/test_m01_deletion.py::test_branched_graph_exact_deletion_and_uncertain_commit.

R-MPV13 IF revision/DDL/payload/method/graph/intent/recovery authority is unknown or inconsistent, THEN startup and ops recovery SHALL fail closed; only explicitly registered old/new adapters SHALL validate a new-target restore while retaining latest tombstones, legacy roots/MT and revoked sessions. R-MPV14 WHEN the selected project/version/job changes, THE App SHALL bind a separately typed physical instrument to actual owner-scoped API data, reset stale private state, show literal correction/transform quantities and uncertainty kinds with meaningful controls, and never render flag-only output as physical correction or inversion. Gate: frontend/e2e/m01-physical-live.spec.ts::real_selected_project_parameter_effect_and_export and frontend/src/api/m01-physical-contracts.test.ts::reject_cross_variant_and_stale_identity.
