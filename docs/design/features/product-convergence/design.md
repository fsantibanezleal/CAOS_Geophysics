# Product convergence ledger design

The replacement SDD supersedes the fixed-case design whose earlier tasks were marked complete. Its 19 EARS requirements have no machine-readable product verdict yet. This unit implements that missing contract; it does not solve the outstanding scientific or operational gates.

`docs/design/convergence.json` stores the SDD SHA-256, assessed source revision/date, release state, and one requirement record per declaration in section 9. Records contain the exact gate text, one of pass/fail/unresolved/ineligible, a literal scope note, and evidence references. A passing record requires a measured receipt for each declared executable gate with its content hash and gate source hash, plus hashed evidence for declared documents. A changed gate invalidates the receipt. Documents can explain a finding but cannot replace measured execution. The R-018 ledger itself is validated structurally rather than including its own hash inside itself, which would require a cryptographic fixed point. Ineligible is useful for a specific dataset, not acceptance of the product requirement.

The stdlib checker parses the numbered product declarations, compares coverage and exact gate text, checks repository-contained evidence paths and digests, and checks named Python gate functions when a receipt claims execution. For documentation/JSON/browser gates it checks the actual named file; content review and browser correctness remain independent oracles. The checker cannot establish science by inspecting text and says so explicitly. Passing evidence attests an invocation, not correctness of an unmeasured claim. No receipt is manufactured by this unit.

Two distinct commands prevent green-check ambiguity. The default validates ledger structure and reports every non-pass, so incomplete development may be persisted without calling it released. `--require-release` additionally refuses any non-pass, an unaccepted replacement, or more than one application origin. Both return nonzero for invalid evidence. Neither downloads data, trains, solves or regenerates truth. Local adversarial tests exercise missing/duplicate requirements, changed gate declarations, evidence tampering, absent functions, traversal, and unsafe release state. CI may run the cheap structural checker only, not the local tests or release acceptance.

Initial records conservatively remain unresolved wherever the full product gate has not been executed. Partial merged work is recorded as evidence notes, especially M13 parity and the independently retained M12 failure. A useful negative benchmark is not an accepted inversion. The one-VPS cutover remains unexecuted and the legacy deployment remains intact while its replacement is incomplete.
