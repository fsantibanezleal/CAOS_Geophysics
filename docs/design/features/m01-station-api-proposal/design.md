# Proposed M01 exact station upload and correction child SDD

Date: 2026-10-03. Design only, **not approved for implementation**. Main owns approval, coordination, branch assignment, backend/runtime and final promotion. Parent approved product SDD sections 2/3/7, R-002..R-007/R-009/R-011; local correction and transform units remain bounded subfeatures, not full M01 acceptance. [Research](research.md) was inspected before writing this proposal.

## Bounded feature

Support authenticated private upload of exact existing gravity-stations-1 JSON and a true station-correction child dataset. Do not include provider acquisition, generic CSV conversion, raw instrument reduction, automatic datum/projection/error inference, transform jobs, frontend activation, ops-script execution, API host approval, merge or deployment.

One reviewed method discriminator is proposed: gravity.station-corrections/v1, distinct from gravity.station-outlier-flags/v1 and from a full M01 method claim. The actual route/dispatcher names are assigned by main after MT runtime convergence. No function, schema or shared backend file is edited by this proposal.

## Transport and dataset boundary

Extend the existing owned raw-upload transport with a reviewed gravity_stations_json format discriminator, JSON MIME/type detection and an explicit exact-schema physical-metadata mode. Do not run this format through the existing generic CSV PhysicalInput or reconstruct station physics from form defaults. Retain existing private-storage attestation, source/rights/attribution, owner/project checks and upload filename safety. Main decides the concrete typed union and route integration; it must not weaken existing CSV/MT upload security.

The raw asset retains exact bytes, byte count and hash outside the public web root. Strict JSON parsing rejects duplicate keys, nonfinite constants, booleans as numbers, wrong types/unknown keys and excessive structure before scientific computation. A proposed initial bounded envelope is 16 MiB, 1..400 stations, nesting depth 16, reviewed metadata string lengths, account/project quotas and no compressed/object arrays or provider code. These are proposed ceilings, not measured host admission. Larger surveys stay explicitly offline; no automatic thinning or changed resolution occurs.

Create a distinct API dataset envelope with owner/project/raw/parser/version identities and an unchanged gravity-stations-1 scientific payload. Its source_sha256 is retained supplied provenance; its raw byte hash and canonical scientific payload hash are separate server receipts. Do not insert API identities into the strict scientific object. The original observation dataset is immutable, with current state and known history explicit. Structural/raw integrity acceptance does not itself authorize a correction or establish field eligibility.

The first reviewed adapter admits documented calibrated absolute observations and known replayable corrected states supported by the local function. Counts, unspecified legacy anomalies, unknown operational metadata, unmapped instrument variants and unresolved principal facts have typed ineligibility reasons. They are not translated into this schema automatically. The exact gravity-stations-1 payload has no mask field: do not add one or silently exclude stations. Preserve QC outlier flags as derived diagnostics, never automatic exclusions. The transform's separately supplied mask/geometry contract remains a later boundary, not an invented correction-upload field.

## Child execution and scientific identity

The API handles bounded schema/admission and queue transactions; it never runs normal-field/Bouguer/terrain numerics in request or background-task processes. The existing distinct worker launches one fixed allowlisted child executable/adapter, without shell interpolation, dynamic package/provider imports, pickle or arbitrary user scripts. Adapter inputs are exact verified private scientific payload, explicit reviewed correction config and job identity. Outputs are the existing process_survey result, wrapped separately with job/dataset ownership/version identity and execution receipts.

Pin Boule/Harmonica and all numerical dependencies to the reviewed local engines, using a separately main-owned runtime environment and parity tests. Never modify another agent's environment as part of integration. Validate current-state replay/history, unit/sign/datum/reference and explicit instrument-processing statuses. The adapter does not add unavailable drift/tide or reference conversions. An already-applied stage cannot be repeated with contradictory parameters. Duplicate logical requests must return a typed conflict or the existing matching immutable identity, not apply another correction silently.

On verified success, persist a new child dataset plus correction result/QC/error records, linked to parent dataset version, parent raw/hash, correction config hash, method/adapter version, job/attempt, engine/module identity, output hashes and measured resources. Store current corrected values separately from original_value and retained units/sign; preserve source rights, QC flags, original metadata and every history addition. Conservative contribution sums retain bound semantics, not mislabeled SD/covariance. A later transform requires its separate station-keyed metric/error/component/source-free declaration and remains outside this feature.

Publish the child files exclusively and mark success transactionally only after identity verification. Failure/cancel/timeout/pin drift/partial output produce a durable non-success record, no public result and no replacement of original bytes. Retry is a new attempt, never overwriting prior successful children. Account derived-byte accounting, reservation, deletion, export and backup/restore must include this new child kind. A private export/import must recheck raw, parent, job, scientific correction and byte identities; no field source is copied into public static assets, repo evidence or logs.

## Approval and unknown-variant adapter rule

Separate scientific contract eligibility, reviewed adapter availability and actual host approval. Proposed registry fields: scientific_eligible, adapter_reviewed, host_approved, pin_compatible and resource_admissible. Dispatch/submit/worker all fail closed if required fields are absent or false. host_approved is false by default. No feature flag, CSV parser, local analytical control, successful upload or ops recovery test may turn it on automatically.

Actual host receipts must cover nominal, reviewed upper-bound and malformed input; peak wall/RSS/scratch, 30% headroom, quotas/concurrency, cancellation/timeout/crash recovery, concurrent API responsiveness and exact local/child numerical parity. Main reviews that measured receipt and owns the approval decision. If the host cannot meet scientifically valid resolution, preserve the complete offline recipe instead of substituting a smaller unnamed calculation.

Unknown ops or instrument variants are not wildcard adapter registrations. Each needs an explicit named mapping, pinned source/engine/config identity, legal/private-storage decision, independent physics/error/sign/unit oracle and host bounds before dispatch. The current Bartlett author 2929-row profile cannot enter this first bounded contract: datum, sigma and original-lineage gaps remain unresolved, plus it exceeds the reviewed station ceiling. No new field acceptance claim follows from this feature proposal.

## Ownership seam and implementation order

Main owns app/schemas.py, formats.py, models/migrations, private storage/projects, processing contracts/routes, method registry, worker/compute dispatch, bundle/export, API/runtime requirements, MT adapter convergence and host approval. A future explicitly assigned M01 integration owner can own a separate ordinary scientific adapter and its tests; overlapping shared-path changes require main coordination, not parallel edits now. The existing local gravity_processing.py and its exact numerical gates remain the scientific source of truth. The transform geometry boundary is reused only in a subsequent independently assigned integration feature.

After current units/MT runtime converge: re-inspect shared dispatcher contracts, obtain main's feature/ownership approval, write prospective API tests first, implement strict upload/parser child boundary, prove real local-child parity and private immutable lifecycle, run full API/security/regression checks, then obtain actual-host evidence. Keep host/API approval false until the separate receipt is reviewed. Frontend original/derived correction-state/error views and EN/ES/theme/device QA are a later assigned step. No backend edits occur before that handoff.

The prospective case/state/error matrix and exact scientific-schema limits are in [validation plan](validation-plan.md). Private-storage attestation and public redistribution rights are separate checks; all new source and child bytes remain private even when an upstream licence permits redistribution, unless main explicitly authorizes a different publication workflow.
