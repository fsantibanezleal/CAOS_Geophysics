# Proposed station correction API validation and ownership plan

Status: design-only continuation. These are prospective acceptance cases, not implemented tests or an API activation. Main retains shared-path ownership, MT/container/STEAD coordination and actual-host approval. No API, worker, adapter, schema migration, runtime environment or source intake code is edited here.

## Scientific contract boundaries checked against current local code

gravity-stations-1 has schema_version, state, metadata, stations and history, with strict known keys. API owner/project/version identities belong in a separate envelope. Each station retains latitude_deg/longitude_deg and receiver/surface heights, original_value/value_mgal and explicit gravity/height/latitude errors. Orthometric inputs require a named geoid plus per-station geoid values/errors. EPSG:4326 annotations and WGS84 reference are not interchangeable with a projected-XY CSV. The correction schema has no mask, easting/northing, transform candidates or arbitrary component-name field. Do not add any of those to make an uploaded file fit a generic UI form.

Known original gravity units/sign conversion is already handled by the local function; accepting an explicitly known conversion is not guessing units. No API-specific normalization may alter original values, metadata or the original byte hash. source_kind=synthetic_control/field remains the uploader's explicitly checked classification, not an API inference from a filename. A valid source SHA-256 is supplied provenance; verifying actual provider bytes is separate from verifying uploaded transport bytes. Retain both hashes and their meanings.

Local correction uncertainty permits finite nonnegative primitive SDs, including a genuine zero for a deterministic authored control. That is different from the transform's required positive fit SD. Missing/null error is never a zero. conservative_marginals is a contribution-sum bound, not covariance or standard deviation; preserve that type through the child and export. Do not falsely reject a valid correction child solely because a later transform would be ineligible, and do not make the later transform eligible by manufacturing positive sigma.

## State and failure semantics for main review

1. Raw asset: private exact bytes and owner/source/transport receipt. Bounded transport success alone says nothing about scientific modelling eligibility. Absence of public mirroring rights does not necessarily forbid explicitly permitted private storage.
2. Parsed dataset: immutable scientific payload plus separate API identity and verdict. Invalid physics remains an ineligible raw object or a typed rejection under the existing main-owned policy, never a fabricated scientific dataset.
3. Candidate correction: explicit target/config and replayable input state. Report separate contract, adapter, pin, resource and actual-host approval checks. Method discovery may expose a blocked reason while host_approved stays false; it must not claim a submitted numerical job ran.
4. Job: only a main-approved fixed adapter/host lane can enter queued/running. API request/background processes do not perform correction numerics. Worker rechecks identities and approval rather than trusting a stale submit-time flag.
5. Child: verified complete scientific result plus new owner-scoped child version and full parent/job/attempt identity. A staging directory or partial result is not a child. Duplicate requests must preserve exact identities or return a conflict, not append another physical correction.
6. Export/re-import/restore: preserve original values, current state, additions, flags and exact error kind. Integrity failures, permission failures and cancelled/failed jobs cannot yield a success bundle. No private source citation, station values or raw bytes enter public logs/static pages/Git.

Proposed error families, to be aligned with main's existing ApiError vocabulary: private permission/owner boundary; byte/schema/physical contract; lineage/dataset integrity; adapter/pin compatibility; host/resource admission; cancellation/timeout/crash/partial publication; quota/export/restore integrity. Return field paths and a safe reason, not raw input or full provider metadata. HTTP status, retry/idempotency and reconciliation choices require main's review; this plan does not reserve incompatible shared endpoints or change current error codes.

## Owned handoff and stop points

Main approves the feature, assigns the exclusive implementation worktree, resolves overlapping app/schema/storage/registry/worker/export/migration paths and verifies MT runtime convergence. The prospective integration owner implements the ordinary fixed M01 adapter and scoped tests only after that assignment. Main/ops owns measured host receipts and the separate approval decision. Frontend/API presentation and EN/ES/theme/device integration need a later explicit owner; no routes or files are silently reserved by this design.

Proposed caps (16 MiB, 1..400 correction stations, depth 16 and reviewed metadata string lengths) remain review candidates, not benchmarks or mandatory amendments to the existing local 10000-station correction ceiling. The transform's 20..400 retained-geometry limit is a separate dense method constraint. Never select a convenience subset of the author 2929-row data or invent datum/errors to fit these limits. Full M01/field/release acceptance remains open even after a bounded correction adapter passes.
