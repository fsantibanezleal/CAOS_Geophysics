## Intake objects and identity

An intake consists of immutable UTF-8 CSV bytes and an immutable UTF-8 JSON sidecar. SHA-256 is computed separately on exact original bytes, before normalization. A derivative never replaces the originals. No archive, URL, executable, remote path, embedded binary or spreadsheet formula is accepted. CSV header is exact and unique; BOM presence is recorded then stripped only for decoding. Duplicate JSON keys, nonfinite numbers, booleans-as-numbers, exponent overflow, invalid UTF-8, trailing JSON tokens, path traversal and resource-limit breaches fail before numerical work.

CSV columns, in this exact order:

`row_id,line_id,line_kind,sensor_id,ordinal,utc,easting_m,northing_m,upward_m,terrain_upward_m,clearance_m,magnetic_nT,uncertainty_nT,heading_deg`

row_id is unique ASCII `[A-Za-z0-9_.-]{1,64}`. line_id and sensor_id use the same syntax; line_kind is flight, tie or reflight. ordinal is a nonnegative integer, strictly increasing within each line/sensor as encountered. Interleaving sensors is legal and does not reorder records. UTC is either empty or an ISO-8601 Z timestamp with documented precision; no synthesized date. Float fields use finite decimal ASCII, no locale separators; empty is null, never zero. Only magnetic_nT, uncertainty_nT, utc and height/terrain/clearance/heading may be null for inspection. XY, identity and ordinal are required. Every row survives into the output inventory, including rejected measurements; duplicate coordinates/times receive diagnostics, not averaging. A segment joins only consecutive records of one line/sensor with admitted geometry, values and declared maximum gap. Sensor channels are fitted separately; concatenation or scalar averaging across sensors is unsupported.

Sidecar exact top-level keys:

Nested key sets are equally exact. Dictionaries and text count toward node/byte limits. Sidecar plus request together must fit the 2 MiB metadata ceiling; auxiliary navigation/base/calibration series are embedded typed arrays in the relevant operation parameters and count toward it. Each series records exact keys schema, source_sha256, rights_decision, clock, coordinate_or_quantity_definition, records; each record has utc plus the fields specified for that operation below. Their original byte identity and derivative manifest are verified before embedding; no URL/file dereference or unbounded secondary loader is permitted. A rights attestation permits only its stated lane, never authenticates the provider. Missing source rights keeps provider acquisition blocked. User data with documented private-processing permission may remain private; public export is independently decided. Hashes establish byte identity, not scientific truth, a license or access authority.

## Physical eligibility tiers

Structural inspection requires valid identity, scalar units and metric XY. It may expose absent heights/times/uncertainty without authorizing corrections. Raw scalar total intensity is admitted for inspection/correction; harmonic fitting requires an eligible scalar anomaly with documented main-field removal or a separately justified constant-background weak-anomaly control. The magnitude of a spatially varying vector main field is not automatically a harmonic scalar. Geometric same-plane interpolation requires a known common vertical datum, finite heights and a user-declared maximum height mismatch whose adequacy is documented; the result remains an elevation approximation. Harmonic height transfer requires actual upward coordinates for every fitted/predicted sample, one compatible datum and a declared source-free domain above all source positions. clearance is not upward: it can be derived only from eligible terrain in the same datum, retaining evidence. supplied clearance, height and terrain must agree within the supplied tolerance; absence of tolerance makes this consistency check unresolved. There is no universal instrument-height tolerance.

Crossovers require actual flight/tie geometry, same admitted channel/sensor policy, no masked bracket/gap and an explicit max height separation, optional max temporal separation, and nonparallel intersecting segments. A height-mismatched crossing is not a valid equality constraint. Optional uncertainties support conditional inverse-variance fits only if their meaning and independence are supplied; otherwise use unweighted fits and unweighted nT metrics. No reduced chi-square or field confidence interval without an admitted error model.

## Immutable correction DAG

Each channel-state entry has exact keys operation, status, parent_channel_sha256, output_channel_sha256 nullable, evidence_sha256 nullable, parameters, units, sign, applied_by. operation is lag, diurnal, heading, main_field, leveling or microlevel. status is not_applied, applied or unknown. The initial supplied channel can list provider-applied/unknown operations without inventing their parameters. An application needs not_applied for that operation and all dependency inputs; it appends a new record. A requested re-reference is a distinct operation with both exact old/new evaluated scalar fields. Unknown old reference cannot be reversed. Diagnostic arrays are not promoted into corrected channels automatically.

Lag parameters contain signed tau_s, definition `position_time = measurement_time + tau_s`, synchronized navigation_series_sha256, clock evidence and interpolation policy. Nav series contains strictly increasing UTC/easting/northing/upward with the same datum. Linear interpolation only inside brackets; outside overlap and excessive gaps are masks. Values stay at their measurement time; no wrap/endpoint fill. A known provider-applied lag cannot be reapplied.

Diurnal parameters contain base_series_sha256, unit nT, clock/datum evidence, base_reference_nT and valid intervals. Subtract `base(t) - base_reference_nT`; missing synchronized brackets are masks. A base absolute field must not be subtracted as a perturbation. Heading parameters contain independently calibrated a0, ac, as in nT and convention clockwise-from-north; subtract `a0 + ac*cos(h) + as*sin(h)`. Calibration source/partition is explicit and cannot use sealed test samples. Platform compensation from full attitude/sensor vectors is outside this scalar heading model.

Reference exact keys: model_generation, coefficients_sha256, evaluator_name, evaluator_revision, evaluator_source_sha256, date_decimal_year, coordinates_sha256, input_height_definition, datum_transform_evidence_sha256 nullable, original_basis, output_basis ENU, vector_east_nT, vector_north_nT, vector_up_nT, scalar_F_nT, direction_tolerance_deg, receipt_sha256. Arrays are row-indexed; scalar F equals the vector norm within stated evaluator rounding tolerance. The receipt must describe main field, not secular variation, and valid epoch interpolation. IGRF14 nominal date domain is 1900..2030; no accidental 2035 extrapolation. NOAA Fortran geodetic input is described as km above sea level but uses a reference spheroid: implementation review must resolve datum conversion in its evaluator receipt, never assume GPS/orthometric equivalence. NOAA NED X,Y,Z becomes ENU Y,X,-Z. Decimal year derives from genuine timestamps or an explicitly documented survey reference epoch, not a file modification date.

The scalar harmonic anomaly lane uses a spatially constant inducing direction approximation whose maximum row direction spread is recorded and must meet a user-declared tolerance no greater than 0.5 degree for this bounded v1. That ceiling is an engineering approximation bound, not proof of negligible geological bias. A variable-direction total-intensity field is inspection-only until an extended vector-aware model is reviewed. Subtracting a row reference F from T is a scalar anomaly operation; projecting a vector perturbation is a weak-anomaly approximation and is separately labelled. Remanence can exist; it invalidates default induced-only RTP reasoning, not the existence of a measured scalar anomaly. RTP is always unsupported in v1.

## Request, resource and partition shapes

The numerical request exact keys are schema `magnetic-request/1`, dataset_version_sha256, channel_sha256, sensor_id, operations, geometry_policy, grid, equivalent_sources, split, spectrum, export_policy. Operations are explicit ordered enumerations with typed parameters; no expression, callback or arbitrary module. Grid contains origin_e_m, origin_n_m, spacing_e_m, spacing_n_m, nx, ny, plane_upward_m, datum, support_radius_m, continuation_delta_m nullable, boundary_policy. Positive spacing and integer dimensions are mandatory; all requested exported cells together <=16,384, including additional diagnostic planes. Padding is explicit, at most twofold per axis and <=65,536 internal FFT cells; it is counted in RSS/scratch preflight, never presented as observations.

Equivalent-sources config contains explicit source_geometry, depth_candidates_m (two positive numbers), damping_candidates (four finite positive values), weights_policy unweighted or admitted_inverse_variance, dtype float64, parallel false. The eight depth/damping combinations, three inner folds, one final fit and one geometric comparator give a total ceiling of 26 fits. Solver failure is reported, not replaced by a different parameter. Source centers derive only from training geometry with explicit source block size; all observations remain in objective/residual inventories. Bounds are those in design: 400 rows including masked rows, 32 lines, 4 sensors, 399 segments, 4,096 enumerated segment comparisons/crossovers, 256 sources, 26 fits, 16 MiB CSV, 2 MiB sidecar, 8 MiB result, JSON depth 16/nodes 200,000/key 128/text 8,192/numeric token 128 bytes. Enumeration must fail before native work if a ceiling is exceeded. No downsampling or auto-coarsening.

Split contains geometry_policy_version, outer_line_ids, heldout_blocks, buffer_m, three_inner_fold_line_ids, geometry_manifest_sha256, sealed_values_sha256, tuning_candidate_order and evaluation_count. Selection is made from geometry/IDs before channel-value operations. Buffer must be at least the declared support radius; training tie samples inside heldout blocks plus buffer are excluded with masks. Full line/sensor IDs cannot cross train/test or inner train/validation. Less than four geographically usable training groups makes tuned evaluation ineligible, not a request for random K-fold. The sealed record has one evaluation; a subsequent parameter change creates a new explicitly exploratory assessment, never another untouched test claim.

## Result and failure schema

Result exact top-level keys are schema `magnetic-result/1`, run_id, lane, input, request, environment, inventory, channels, geometry, crossovers, leveling, partitions, fit, grid, spectrum, evaluation, rights, artifacts, verdict. lane is local_synthetic, local_user, field_provider_product or future_online_owned, never inferred from shape. All array descriptors contain shape, dtype, unit, ordered_ids_sha256, values_sha256 and mask_sha256. Numeric serialization uses finite numbers or null plus explicit mask codes; NaN/Infinity are forbidden. Inventory accounts for all original rows: retained + invalid + excluded identities exactly equals input; overlapping reason sets are separately counted. Original and derivative channels have different hashes. Residual sign is observed minus predicted; crossover sign is flight minus tie. Output ordering is source-order rows, lexicographically ordered crossover IDs, and row-major northing-increasing/easting-increasing grids with explicit coordinate arrays.

Mask codes include missing_value, duplicate_identity_error, duplicate_location, invalid_geometry, gap, unsupported_time, height_mismatch, uncalibrated_line, outer_sealed, spatial_buffer, outside_hull, beyond_support_radius, sampling_unresolved and unsupported_operation. Diagnostic flags are distinct from exclusion policy. Unsupported/invalid cells have null values, not zeros. No hull claim substitutes for distance, line spacing or source-free checks.

Verdict is pass, fail, unresolved, ineligible, nonconverged, cancelled or resource_refused with per-gate evidence and field paths. Only complete eligible numerical success can publish a result. Error includes code, stage, field nullable, observed, limit nullable, reason, local_recipe nullable and attempt identity; sensitive raw paths/values do not enter public messages. Partial staging evidence is durable non-success. Rights-filtered export has member allow/deny records; denied raw data never enter a ZIP merely because the derivative is public. Export to an existing destination fails. Replay validates exact input/request/environment hashes and array tolerances, not just a successful exit.

## Online port and durability boundary

Future frontend magnetic-contracts.ts and app/magnetic_contract.py share exact method `magnetic.flight-line-processing/v1`. Capability response contains state CLOSED, reasons, bounds, required_metadata, local_recipe and admission_receipt_sha256 null until approved. CLOSED submissions return method_unadmitted and dispatch_count zero. Request references owned dataset_version_id and numerical_request_sha256; it cannot import arbitrary caller-supplied path/ownership/hash authority. A future OPEN receipt must pin core/schema/native controller/profile/runtime and persistence extension. Existing gravity profiles do not confer admission.

Attempt state sequence queued -> running -> succeeded/failed/cancelled/interrupted/resource_refused; retry creates a new attempt, never rewrites terminal identity. Native process-tree CPU, wall, RSS, scratch, controller CPU and stop reserve have independent counters. Whole-child ceilings are 60 s CPU/120 s wall/512 MiB RSS/64 MiB scratch, stop at 50 CPU seconds with verified <=10 s reserve; controller <=10 s. Startup/import/recovery rejects unregistered M03, owner mismatch, tombstones, hash mismatch, partial file/DB publication and result-to-request mismatch. Persistence owner must define atomic publish, private staging retention, deletion/tombstone authority and export/import inventory in their reviewed extension. This packet does not edit those systems.

## Linked scientific view payload

The view adapter consumes result arrays, never recomputes a scientific result in the browser. Selected identity is row_id, segment_id, crossover_id or grid_cell_id plus run/request hash. Map segments carry source endpoints, partition/mask and flight/tie role; profile values keep acquired order and separate nT/m axes; crossover links carry bracket IDs/weights, signed difference or rejection; residual uses observed-minus-predicted nT with training/heldout labels; spectrum uses explicit cycles/m or rad/m and nT^2 bin power. Keyboard focus and selection synchronize all five panels. Pan/zoom cannot alter request identity; scientific parameter changes enqueue a real new computation only when admitted. EN/ES labels and light/dark masks must preserve null versus zero and pending old-result identity. Follow the ADR-shell and layout links in design, with render gates in validation.
