# M13 browser picker sidecar

Status: implementation under the approved product SDD, stacked on PR84. This sidecar supplies an executable browser inference path and input/asset validation. PR84 supplies the reviewed model and held-out assets; this sidecar supplies no new scientific assets, field-accuracy claim or public release.

## Runtime and scientific boundary

ONNX Runtime Web executes the exported `waveform` float32 tensor `[1,3,6000]` on the WASM provider. The ONNX graph returns `probabilities` `[1,3,6000]` ordered N/P/S. The application validates every returned sample for finite values, range `[0,1]` and per-sample class sum within `1e-3` before drawing or selecting arrivals. P and S use global maxima and fixed 0.8 thresholds. If both pass, S abstains when its peak is fewer than 40 samples after P. This matches `data-pipeline/phase_model.py`; a model score is not a calibrated uncertainty.

The input window is 60 seconds at 100 Hz with E/N/Z measured channels. Raw unrestituted counts receive exactly the local STEAD transform: float64 component mean, float32 cast of samples and mean, float32 subtraction, float32 absolute peak and component-wise division. The already-normalized representation bypasses this transform. Missing, flat, duplicated, nonfinite, wrong-rate, wrong-length, response-corrected, gapped or declared clipped inputs are rejected. The waveform plot uses the same normalized values passed to ONNX, even when the uploaded representation is counts; it does not display raw counts against a dimensionless scale. The UI labels source and representation, relative seconds, waveform units, score units, model hash, and abstentions. It never reads analyst picks to choose an arrival.

## Inputs and frozen asset seam

Local users can supply an ONNX file and a JSON trace in the documented `caos.phase-browser-trace.v1` format. Local files have unverified scientific provenance; running a file is not a held-out benchmark. A separate same-origin manifest loader targets `data/phase/stead/manifest.json` under the existing deployment base. It parses the frozen `caos.phase-browser-assets.v1` `input`, `output`, `model`, `benchmark`, `selection`, `source` and `records` fields. Its model, benchmark and trace bytes are SHA-256 checked in the browser. Each `qc-valid` entry names one little-endian ENZ component-major float32 file (72,000 bytes); the `qc-rejected` entry has a reason and no waveform path. The declared selection has 24 entries, 23 valid and one quarantined. All 24 remain selectable/inspectable. A QC-failed selection never calls inference or substitutes a different trace. The scientific bytes and manifest arrive only through the merged PR84 ancestry, not the sidecar commit.

PR84 tracks `data/derived/phase/browser-assets/stead/{manifest.json,model.onnx,...}` after sealed evaluation and asset rights review. Its copy step places these in `frontend/public-release/data/phase/stead/` for build and development; this sidecar does not edit that copy step or the scientific bytes. The local browser parity gate compares the 23 valid browser outputs with the private frozen PyTorch oracle (max absolute error <= 0.001, peak difference <= one 0.01 s sample) while retaining the QC exclusion. Release acceptance still requires its own asset/receipt verification, deployment and performance review; M08/M13 accuracy belongs only to the locked 6,000-trace test population.

## UI and verification

The instrument belongs to the existing Benchmark route, reachable from the six-route navigation and M13 implementation section. It separates local-file inference from the curated-asset loader, shows explicit loading/error/unsupported/abstention states, displays a hash-checked 6,000-record offline M08/M13 metric table, and plots E/N/Z waveform and N/P/S score curves over a linked, controllable time window. These are direct model outputs; display decimation cannot influence arrival selection. Unit tests cover input contracts, float32 normalization, exact peak/abstention semantics and output validation. The local browser parity script executes the final manifest's 23 real traces against the private PyTorch oracle using the actual Vite public directory without request interception; the LF-normalized manifest SHA-256 `a8c49f06bef91b95ada8270628750824230b295b17a14f8941853a1620733d1c` passed with maximum absolute error `4.41e-6` and zero peak-sample error. The built-bundle UI check covers desktop EN/light and phone ES/dark with the copied real asset bytes. The private oracle was read outside the repository and was not copied into the browser or public output. This is a local verification result; public hosting and release acceptance remain separate.
