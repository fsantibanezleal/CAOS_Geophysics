# M01 station corrections: primary-source dossier

Date: 2026-10-03. Scope: local gravity station corrections and QC, issue #43.

## Verified sources and consequences

1. [Boule 0.5 normal gravity](https://www.fatiando.org/boule/v0.5.0/user_guide/normal_gravity.html), inspected 2026-10-03, implements height-dependent normal gravity. Its closed-form calculation follows Lakshmanan, [10.1190/1.1443090](https://doi.org/10.1190/1.1443090), and Li and Gotze, [10.1190/1.1487109](https://doi.org/10.1190/1.1487109), as listed in the [official references](https://www.fatiando.org/boule/v0.5.0/references.html). These DOI identities were checked against the official bibliography; the papers were not independently obtained. Boule 0.6 is now current and changed the coordinate API. Use the explicitly pinned 0.5 API, `WGS84.normal_gravity(latitude, height)`, rather than silently accepting API drift. Runtime code calls the real engine.
2. [Harmonica 0.7 Bouguer correction](https://www.fatiando.org/harmonica/v0.7.0/api/generated/harmonica.bouguer_correction.html) gives the infinite-plate effect `B = 2*pi*G*rho*t` in mGal, with SI density and ellipsoidal topography. The returned land attraction is subtracted. The [official implementation](https://www.fatiando.org/harmonica/v0.7.0/_modules/harmonica/_gravity_corrections.html) is checked locally for its gravitational constant. Negative topography invokes a water/crust contrast in that API. This unit instead rejects below-ellipsoid land and marine surveys because their mass/reference geometry is outside its reviewed contract.
3. [Harmonica topographic correction](https://www.fatiando.org/harmonica/latest/user_guide/topographic_correction.html) distinguishes a plate from a DEM/prism total effect. Subtracting the total terrain attraction after subtracting the plate removes mass twice. Accept only a supplied, signed **additive residual to the selected plate** (`B - terrain_total_effect`) with density, height reference, method, uncertainty and source hash. No DEM-derived effect is fabricated or inferred.
4. [Fatiando gravity-processing tutorial](https://www.fatiando.org/tutorials/notebooks/gravity-processing.html) explicitly converts orthometric to ellipsoidal heights using the geoid. Use `h = H + N` for both receiver and topographic surface, with a named geoid and documented uncertainties. Receiver height is not automatically plate thickness.
5. Kennedy, Pool and Carruth (2021), [USGS report 10.3133/tm2D4](https://www.usgs.gov/publications/procedures-field-data-collection-processing-quality-assurance-and-quality-control-and), covers gravity collection, network adjustment, calibration, QC and archival. Its landing-page content was obtained; the full report fetch returned 403. No exact instrument correction formula is attributed to unread PDF text. Raw relative-meter counts, drift/tidal/network corrections and reference-system conversion cannot be invented from station coordinates. Require calibrated, absolute, downward-positive gravity or an explicit sign conversion, instrument/tide status, named gravity datum and processing citation.

## Formula and independent oracle

Let `g` be downward-positive observed gravity in mGal, `phi` geodetic latitude and `h` WGS84 ellipsoidal receiver height. Define `gamma0 = gamma(phi,0)`, `E = gamma0-gamma(phi,h)` and `D = g-gamma0+E`. This is the gravity **disturbance**, not a legacy free-air anomaly on an unspecified height datum. The two lineage additions are `-gamma0` and `E`; there is no additional `0.3086*h` operation.

At the ellipsoid, the independent Somigliana expression is `gamma = gamma_e*(1+k*sin(phi)^2)/sqrt(1-e^2*sin(phi)^2)`, with the WGS84 constants tabulated by [USGS Open-File Report 2006-1204, computations](https://pubs.usgs.gov/of/2006/1204/Gravity/computations.pdf). The initial `2e-6 mGal` tolerance failed because the published ten-decimal SI pole constant is truncated, not exact: one final decimal place is `1e-10 m/s^2 = 1e-5 mGal`. The independent precision-bound tolerance is therefore `1e-5 mGal`, decided from the constant precision; the observed maximum discrepancy is `6.307e-6 mGal`. Plate parity uses `G=6.67430e-11 m^3 kg^-1 s^-2` and `1 m/s^2 = 1e5 mGal`; tolerance `1e-10 mGal`. Zero-height, north/south symmetry, decreasing gamma with height and the official 45-degree/1000-m value independently constrain elevation behavior. Height-uncertainty derivatives are compared with a backward difference of the independently published Boule 45-degree table (three rows spanning 777.777 to 1000 m), tolerance `3e-7 mGal/m` on its half-metre SD contribution. The first attempted constant-gradient control omitted height dependence; a low-order flattening/height expansion also omitted terms significant at this precision. Neither approximation is used to alter the closed-form engine calculation.

For land at geometric topographic height `t >= 0`, `DB = D-B`. With a supplied residual terrain addition `T`, `DT = DB+T`. Do not label DT complete Bouguer anomaly: curvature, terrain coverage, density uncertainty and instrumental/reference assumptions remain distinct.

## Uncertainty and evidence boundary

Marginal standard deviations do not establish independence. Offer explicitly selected independent first-order propagation and a conservative sum-of-marginal-contributions alternative. Differentiate the combined height/reference/plate expression, so height effects are not falsely treated as independent duplicate corrections. Treat receiver and surface height errors as separate unless their shared error is supplied; this unit rejects unspecified covariance by requiring an explicit model choice. Orthometric conversion accounts for the common geoid error affecting both heights. Supplied terrain uncertainty represents its total marginal error, including its plate/density dependence; use the conservative model for terrain to avoid assuming independence from the plate.

Synthetic controls are authored numerical inputs, not field measurements. Full M01 retains open field bytes/rights/correction audit, held-out maps, gridding/continuation, online admission, browser and export integration gates. Existing approved product SDD and the user's bounded implementation instruction authorize this feature design without changing the product's acceptance scope.
