# Durable private native result custody

This guide describes the owned custody implementation, not a completed canonical
mount, a new scientific fit, field acceptance or public activation. The scientific
method remains [the explicit offline workflow](22_local_joint_survey.md). Its
[native instrument](../data-contract/04_joint-local-inspection.md) reads original
physical models, responses, residuals, exact exported face-Gram coupling and
frozen selection/holdout states. Browser inspection never replaces scientific
execution. The source-bound compiled optimizer and original precision predicates
remain independent admission gates.

## Complete identity, not a filename association

Every member has the restrictive allocated0006 artifact foreign key
`(job, owner, project, dataset, dataset SHA, method, request SHA)` to the same
seven-field producing-job identity. The request digest is the SHA-256 of the
canonical request JSON, not a caller-supplied substitute. The dataset and all
original source/version/rights/hash dependencies are revalidated before copying,
after copying, at owner read/export and during audit. Changed ownership, source,
request, bytes or index is an error, never a repaired identity.

Literal durable keys are
`derived/{owner}/{project}/joint/{job}/{native member}`; the index remains
`derived/{owner}/{project}/results/{job}.json`. No source path comes from uploaded
metadata. The closed grammar retains `workflow.json`, `failure.json` and the
ordinary native `calibration`, `frozen`, `models`, `result`, `instrument` and
`aborted` members. Both genuine failure ledgers remain original bytes. All names,
sizes, directory identities,1100-file and256MiB caps close before hash/copy.
Every file has independent held/named stat and original SHA checks. Directory
identities close again after the scan; hashes are not cached between scans.

## Publication and uncertain outcomes

`retain_terminal_output` requires the caller's active write transaction and
foreign keys. The parent retains its singleton, source/configuration authority,
native same-connection writer guard and deadline across all awaits. The service
does not commit, roll back, change job state, unlink staging originals or infer
that an SQLAlchemy transaction grants the parent's physical-forest authority.
Successful-job storage additionally requires the actual current-source fixed
child and supervisor admission and rechecks the same deadline after publication.
Failed/cancelled custody never becomes a completed inverse.

Each output and index is exclusive, fsynced and independently reverified before
artifact rows flush. A copy, cancellation, quota, source or commit-ack failure
leaves actual known or uncertain bytes. A cancelled writer is drained before
the caller can release its guard. At most four non-numerical IO workers are live,
with one1MiB buffer each; no numerical resource cap or fsync is removed.
An existing uncertain job tree refuses retry rather than merging/overwriting it.

Artifact bytes are charged in every job state. Failed/cancelled index bytes add
to the canonical success-only index charge. Active joint reservations replace
the generic reservation, not supplement it. `joint_base_derived_usage` preserves
the parent's exact M08/MT/profile baseline; `accounting_delta` is added once.
Publication counts retained stage/scratch bytes plus prospective durable copies
and index against actual remaining quota before first write. The parent's closed
incomplete-custody descriptors continue to charge retained stages; a terminal
state or unreadable directory never authorizes release of their charge.

## Owner-only read and exact private archive

The additive routes are:

- `GET /api/projects/{project}/joint-results`: bounded literal owned-job history.
- `GET /api/projects/{project}/joint-results/{job}`: canonical custody index.
- `GET /api/projects/{project}/joint-results/{job}/members?name=...`: exact held
  original bytes and SHA header, never an arbitrary filesystem path.
- `GET /api/projects/{project}/joint-results/{job}/export`: stored original native
  members plus `private-custody-index.json`, with no recomputed physical arrays.

Every read revalidates source and complete member/index custody, uses the existing
authentication and returns no-store. Literal history also varies on the private
cookie, as do index/member/archive responses. Cross-owner/project requests are404.
The browser binds all seven job fields, literal terminal state, original index
SHA/size, unique stored ZIP member declarations, original member hashes and the
whole native envelope before the existing native inspector accepts values.
Integrity is not authenticity, scientific acceptance or redistribution permission.

The download is a bounded non-seekable Python stored ZIP stream, including
forced ZIP64 native members and the exact private index. Its complete serialized
length is admitted under256MiB before the producer starts. A single queued1MiB
chunk applies backpressure. Original SHA and held/named stat checks plus a final
whole inventory check precede the archive end record. Response completion,
disconnect or repeated cancellation drains the actual producer before request
dependencies can close. The route creates no disk export copy, so an interrupted
download leaves no uncharged duplicate ZIP. Previously uncertain `.exports`
bytes are never removed or adopted by this route and remain recovery-blocking
under the canonical startup audit. Native originals and their charges persist.

The project wrapper has one parent method rail and original input sections,
literal stored history and explicit offline scientific guidance. Clearing views,
changing owner/project or session expiry aborts reads and forgets private browser
state, not server bytes. No automatic scientific submission or destructive retry
occurs. The parent owns the actual canonical mount and rendered interaction gates.

To forget input declarations while remaining in the same owned project, use
**Clear private views, not server bytes**. This clears the original provider,
attribution, rights statement and consent, selected files, indexing receipts,
stored history and imported physical instrument state. It aborts and drains
active reads/uploads; it does not delete original inputs or durable artifacts.
Changing input sections alone is not this explicit forget operation. Session
expiry or a changed owned project removes the old private instrument, and a
late response from an aborted operation cannot repopulate it.

On a narrow viewport, close **Processing controls** before using the main
scientific instrument; reopen it for history or clear actions. Frame/state,
receiver, partition, plane and coupling selectors operate on actual exported
arrays. Separate-property frames have no invented joint coupling. Native frame
JSON remains a post-freeze diagnostic export, not a scientific acceptance flag.

Visible readouts use the shared scientific plot formatter and retain units.
These compact labels are display precision, not a new numerical result. Original
binary arrays, exact JSON exports, manifests and cell-value attributes retain
their original values. Native prism geometry is unchanged, with no interpolated
or invented cells. A four-cell slice of a small custody control is not
high-resolution application coverage; the original24-case matrix has624 actual
attempts, not624 spatial cells. Maximum-count transport fixtures and corrective
scientific acceptance remain separate evidence.

## Native inspection cost and source integrity

Admission reads each original file once. Every NPY header must pass before any
array hash or value decode. At most four small reads or hashes are active, and a
large member is isolated. Original buffers are owned snapshots; required file
and payload hashes reuse those snapshots. Export independently rehashes before
use. A second import rereads every original rather than trusting a previous
import, a declared digest or an unchanged path.

Native profiling reports both wall time and summed read/hash durations. With
concurrent slots, summed durations are not wall time. Qualify resource-sensitive
gates serially after competing gates have terminated, recording source/fixture
identity and that changed scheduling prerequisite. Retain timeout failures; do
not change scientific predicates, source barriers or deadlines to obtain a pass.

## Delete and recovery are not orphan cleanup

`project_manifest` contributes exact index/member paths, lengths and hashes to
the parent's whole-project manifest. `delete_artifact_rows` removes only owned
restrictive rows inside that same caller transaction, after exact rename and
before job/tombstone co-commit. Root/source/family deletion remains the parent's
M01 operation. No second project transaction or new HTTP delete route is created.

`purge_exact_job` accepts only an isolated renamed
`.deleting/{owner}--{project}--derived/joint/{job}` tree. It revalidates every byte
and the complete tree before first unlink. Original durable job paths, unknown,
changed, missing and extra-directory state refuse. The parent must establish
committed tombstone authority first; directory naming alone is not that authority.
`recovery_report` reports exact/missing/changed/unknown files, unknown directories
and measured retained bytes, always with `reconciled: false`. It never adopts,
deletes or reassigns them. Restore/adoption requires the parent's separately
source-bound recovery authority, not an operator guess or a quota reset.
