# Private original joint survey inputs

Use the selected authenticated project's native-input panel. The parent supplies
the verified account/project and places this independent component in its one
processing rail. Indexing is a structural custody operation, not a scientific
run. Actual inversion, calibration, durable freeze and sealed evaluation belong
to the explicit scientific job or [offline workflow](22_local_joint_survey.md).
The [native result instrument](../data-contract/04_joint-local-inspection.md)
inspects exact exported outputs; no inverse executes in the browser.

## Supply the original directories

Select the complete ordinary **development** and **sealed** directories from
the original strict intake. No ZIP, arbitrary path, remote URL or executable is
accepted. The development request declares native mesh/geometry, active masks,
units, bounds, starts, priors, source/correction identities, noise and partitions.
The sealed manifest binds its original held-out rows, observation/noise hashes
and plan. Keep the original bytes and directory inventories unchanged.

The combined envelope is at most40 members and256MiB, with JSON at most256KiB.
Before native/raw reads, the client closes original inventories, descriptors,
lengths, plan and sealed bindings. It verifies bounded literal NPY1 C-order
little-endian headers and both original file/data hashes without decoding
scientific values. It does not interpret sealed observations, run correction,
infer physical eligibility or certify the provider's statements.

Choose **Verify opaque original bytes**, then review provider, attribution,
optional citation/DOI and private-storage rights in the section selector.
Explicitly attest permission for every original. Public redistribution is not
granted by selecting a rights label or by passing structural checks.

## Upload, receipts and structural indexing

Choose **Upload originals and index, not a scientific run**. Each ordinary
member uses the actual authenticated same-origin cookie/CSRF binary endpoint,
closed metadata and its original SHA/length. The server checks ownership,
rights, bounded header/data identity and account quota before exclusive private
publication. The native member limit is80 requests per authenticated owner/hour;
the generic upload limit is unchanged. Never raise either limit to hide failures.

Each successful receipt retains its actual source version, rights, member role,
length and digest. The exact36-member original provider-reference pair is one
supported inventory; explicitly supplied raw/corrections produce their declared
larger inventory, never silently omitted files. Structural indexing submits the
complete unique role/name receipt map. The allocated0006 service co-publishes
the actual immutable root/family and dependencies in one transaction. Its
receipt selects a dataset in the parent sidebar, with scientific acceptance
still false. Family registration is not worker, host or numerical admission.

## Failure, cancellation and private state

Successful receipts survive a transfer failure or local cancellation. There is
no automatic retry or server deletion. The cancelled request may already have
published an uncertain original; preserve it for actual accounting/recovery.
Explicitly continuing skips known receipts and uploads only remaining members,
then retries structural indexing. This deliberate action may publish a new
version of an uncertain original; it never proves the earlier bytes vanished.

**Forget this local selection** clears files, receipts, indexed selection,
provider/citation/DOI/rights/consent from browser state, preserving server
originals. Changing account/project or an expired authenticated session clears
private state and aborts old work. Parent mounts must key the leaf by account
and project and clear their selected dataset as well. No private receipts or
source statement are persisted in localStorage.

Original private download/export/deletion remains governed by actual server
custody. Unknown or uncertain bytes require recovery, not destructive guessing.
The allocated source/artifact schema, canonical family/method unions, selected
runtime policy, singleton execution, durable result publication and full
reconciliation/export/delete must qualify separately before a protected
scientific action is mounted. See [allocated successor](25_joint_schema_successor.md)
and [fixed execution](24_private_joint_execution.md).
