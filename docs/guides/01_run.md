# Local reproduction

Run `scripts/setup.ps1 -Gpu` (Windows) or `scripts/setup.sh --gpu` (Linux). Python 3.12 and NVIDIA-compatible CUDA wheels are required for the GPU validation. `.venv` and `.venv-pipeline` are ignored. No editable package installation is used.

The committed `data/derived/v2` tree is the validated 0.04 release. To regenerate it without changing that tree, run `python data-pipeline/rebuild.py --output data/experiments/reproduction` in the repository's `.venv-pipeline`. This computes all 120 conditions and trains both learned models; full acoustic FWI is GPU intensive and can take a long time. Then run `python data-pipeline/edi.py --fixture-bundle --bootstrap-samples 128 --calibration-realizations 48 --output data/experiments/reproduction/edi`, followed by `python data-pipeline/catalog.py --root data/experiments/reproduction`. The original fixture sources are in `data/fixtures/edi/`. For a single case, use `python data-pipeline/rebuild.py --cases FWI_FAULT --variants reference --output data/experiments/fault-study`. Filtered output stays outside the canonical catalogue.

Run `python tests/run_validation.py`, `python scripts/check_artifacts.py`, and `python scripts/validate_recovery.py` against the committed release. For a regenerated candidate, add `--data data/experiments/reproduction` to both artifact and recovery validators, with `--report data/experiments/reproduction-validation.json` for the latter. Then in `frontend`, run `npm ci`, `npm test`, `npm run build`, and `npm run dev`. The build copies committed results without training. The test runner saves JUnit and GPU environment evidence. The local browser acceptance script is `node frontend/scripts/qa-recovery.mjs` while a frontend server is running at `http://127.0.0.1:5179/`.
