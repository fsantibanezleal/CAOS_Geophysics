# Local reproduction

Run `scripts/setup.ps1 -Gpu` (Windows) or `scripts/setup.sh --gpu` (Linux). Python 3.12 and NVIDIA-compatible CUDA wheels are required for the GPU validation. `.venv` and `.venv-pipeline` are ignored. No editable package installation is used.

The committed `data/derived/v2` tree is the validated release. On Windows, obtain the Clear Lake `cl061` station EDI identified and SHA-256-pinned in `data/source-ledger.json`, save it under the ignored `data/downloads/clear-lake/` path, then run `./scripts/rebuild-release.ps1`. The script fails before a GPU bake if the station source is missing or the output is not under ignored `data/experiments/`. It computes all 120 conditions, trains both learned models, assembles synthetic EDI fixtures and the measured no-inverse tensor screen, builds the catalogue, and runs both release validators. Full acoustic FWI is GPU intensive and can take a long time. Use `-ReuseTrained` only to hash-check and reuse the published frozen checkpoints; case inference still reruns. The original synthetic EDI fixtures are under `data/fixtures/edi/`. To assemble and validate a numerical candidate already baked separately, use `./scripts/rebuild-release.ps1 -Output data/experiments/reproduction -SkipNumerical`. For a single case, use `python data-pipeline/rebuild.py --cases FWI_FAULT --variants reference --output data/experiments/fault-study`. Filtered output stays outside the canonical catalogue.

Run `python tests/run_validation.py`, `python scripts/check_artifacts.py`, and `python scripts/validate_recovery.py` against the committed release. For an ignored candidate, set `INVERSE_EARTH_DATA` and `FWI_RECOVERY_ARTIFACTS` to that candidate before running the complete numerical suite; the release script itself runs the candidate artifact and recovery validators. In `frontend`, run `npm ci`, `npm test`, and `npm run build` for the committed release. To inspect a candidate without changing canonical data, run `node copy-data.mjs --source ../data/experiments/reproduction`, then `npx vite --host 127.0.0.1 --port 5179`; use `node scripts/qa-recovery.mjs`, `node scripts/qa-viewport.mjs`, `node scripts/qa-interactions.mjs`, and `node scripts/qa-field-screen.mjs`. The public build copies committed results without training. The numerical test runner saves JUnit and GPU environment evidence.
