# Deployment

The application has exactly one public origin on the ML VPS. GitHub stores source and performs cheap integrity/build checks; it does not host a second application. The static client uses root-relative assets and Nginx SPA routing. The approved full platform adds a same-origin API, private project files outside the web root and a separate bounded numerical worker. Browser-compatible local calculations require no account; explicit server storage, upload and jobs require an internally provisioned account.

Deploy only source, environments and artifacts whose complete scientific, ownership, worker and UI gates have passed. Never train, run scientific inference, modify an artifact manifest or fetch unreviewed data as a deployment side effect. Retain current plus two rollback releases, measure actual release/project/job disk and memory capacity, and test rollback at the same origin. No SMTP/external email or off-host-backup prerequisite applies to this owner-tested stage. Release rollback directories are not project backups.

[The read-only verifier](17_single_site_verification.md) checks exact served build bytes, direct routes and anonymous account boundaries. Those checks do not establish that the scientific product or worker has passed its gates. Private cutover commands and actual host receipts belong in the management repository. Historical dual-host receipts remain historical and are never instructions to recreate the retired publication.
