# Acquire and inspect external sources locally

This guide covers the source-to-raw boundary and the adapters implemented in this unit. It does not turn a field observation into a geological truth label. `data/source-ledger.json` is the reviewed allowlist; the CLI accepts its stable `source_id`, never an arbitrary network URL. Run the commands from the repository root with Python 3.12 and the offline requirements installed. Use `python data-pipeline/acquire.py --list` to inspect the current modes and provider links.

## Commands and exact outputs

For the two reviewed automatic tutorial objects:

```powershell
python data-pipeline/acquire.py --source-id simpeg-gravity
python data-pipeline/acquire.py --source-id simpeg-magnetics
python data-pipeline/ingest.py --external
```

The paired `scripts/fetch-data.ps1` and `scripts/fetch-data.sh` run the first two commands. `--external` processes *only* these fetchable observation archives. It never opens an EDI, ERT or traveltime file as a tar archive. Each raw archive is stored under ignored `data/downloads/`. The immutable acquisition receipt is under ignored `data/raw/acquisition/<source_id>.json`. Local preprocessing writes `data/raw/processed/<source_id>/<raw-sha256>.npz` plus a `.json` receipt containing source/member hash, row count, units, assumptions, flags and derivative hash. The committed `data/external-preprocessing.json` records an earlier release comparison and is not rewritten by this local workflow.

The tutorial `_data.obs` member has four local Cartesian XYZ coordinates/value columns. The adapter requires at least four finite, unique stations. It adds `sigma_assumed = max(0.03 × SD(value), 1e-12)` for local experiments because the tutorial file has no measured uncertainty. Values beyond six scaled median absolute deviations are flagged without deletion or changed weights. No geographic CRS or instrument error is inferred. Before modelling real data, provide its actual coordinate frame, component convention and uncertainty.

For Clear Lake, retrieve the reviewed EarthScope EDI object and run the selected-source QC:

```powershell
python data-pipeline/acquire.py --source-id clear-lake-cl061
python data-pipeline/ingest.py --source-id clear-lake-cl061
```

If the provider is unavailable but you already have the exact file, pass `--file C:\path\to\USGS-GMEG.2022.cl061.edi` on the acquisition command. The first command verifies exactly 16,411 bytes and the ledger SHA-256 before preserving the original under ignored `data/downloads/clear-lake/`. The second performs transfer-function screening with explicit `units=mt`, `variance_convention=complex` and `rotation=preserve`; it reports 42 frequencies and `one_d_inversion_eligible=false`. It writes no new public artifact or inverse model. The existing [EDI method chapter](../problem-types/mt-recovery.md) describes why the necessary isotropic-1D check fails and why EDI is a processed transfer function rather than raw EM time series. Rebuilding its public QC derivative is a separate, reviewed release step.

For either pyGIMLi provider object, download directly from its fixed upstream link yourself, then verify and retain a local copy:

```powershell
python data-pipeline/acquire.py --source-id pygimli-slagdump --file C:\path\to\slagdump.ohm
python data-pipeline/acquire.py --source-id pygimli-koenigsee --file C:\path\to\koenigsee.sgt
```

These files become hash-verified raw assets with local receipts. The generic `ingest.py --source-id pygimli-slagdump` or `pygimli-koenigsee` still returns a specific unsupported-adapter error; it does not guess a modality. Slagdump now has a separate, strict offline M07 workflow below. Koenigsee still needs its own traveltime pick/geometry vertical. Do not relabel either as CSV, waveforms or synthetic truth, or copy the raw files into `data/derived/` or a public bundle. `stead-metadata` cannot be passed to acquisition or ingestion: it is a provider-link-only catalogue lead for another vertical, not a local verified raw asset.

## M07 Slagdump topographic ERT, local only

The fixed `.ohm` header credits the Federal Bureau of Geology and Resources (BGR) Hannover and Markus Furche, and describes a Wenner array with 2 m spacing and surveyed topography. The fixed upstream example-data tree has no LICENSE, LICENCE, COPYING or COPYRIGHT file. That is **not** permission to redistribute these field measurements; the raw object and per-reading inverse receipt remain ignored. The pinned pyGIMLi package metadata declares Apache-2.0 for its software, which does not settle BGR data rights. The provider example identifies x/z as metres and `R` as resistance; the file does not declare a geographic CRS, absolute vertical datum, electrode contact error, measured current/voltage or an instrument uncertainty.

Use an isolated Python 3.12 environment because the pinned M07 pyGIMLi 1.6.1 needs NumPy 2.4 or newer, whereas the canonical precompute environment pins NumPy 2.2.6. From this repository root on Windows:

```powershell
py -3.12 -m venv .venv-ert
.\.venv-ert\Scripts\python.exe -m pip install -r data-pipeline/requirements-ert.txt
New-Item -ItemType Directory -Force data/downloads/pygimli | Out-Null
Invoke-WebRequest -Uri 'https://raw.githubusercontent.com/gimli-org/example-data/3bab9c6b96a606e2ca12cbdafc8c7da4f1b73c67/ert/slagdump.ohm' -OutFile 'data/downloads/pygimli/.incoming-slagdump.ohm'
.\.venv-ert\Scripts\python.exe data-pipeline/acquire.py --source-id pygimli-slagdump --file data/downloads/pygimli/.incoming-slagdump.ohm
.\.venv-ert\Scripts\python.exe data-pipeline/ert.py --qc-only
.\.venv-ert\Scripts\python.exe data-pipeline/ert.py
```

Acquisition verifies exactly 5,435 bytes and the SHA-256 in the ledger before the immutable ignored `data/downloads/pygimli/slagdump.ohm` is installed. The temporary download is a local working copy, not a public fixture; remove only that exact temporary file after checking the verified receipt if desired. QC rejects count/header drift, nonfinite or unordered sensor x/z, duplicate, out-of-range or non-Wenner 1-based ABMN electrodes, zero/invalid resistance and undeclared extra rows. It preserves all valid readings. A flag-only robust check compares log resistance within AB-span groups, without deleting or reweighting outliers. This 222-reading profile supplies **no reciprocal pair** and no error column, so neither reciprocal precision nor a calibrated chi-square can be inferred.

For current pair A/B and potential pair M/N, transfer resistance is `R = (u_M-u_N)/I` in Ohm. On a flat homogeneous halfspace with pair distances in metres, `k_flat = 2π/(1/r_AM - 1/r_AN - 1/r_BM + 1/r_BN)` and apparent resistivity is `ρ_a = kR` in Ohm m. The local script independently computes this signed analytical factor and checks it against pyGIMLi's flat factor, then uses pyGIMLi's *numerical topographic* factor for the field response and a topography-following 2D inverse. A refined flat homogeneous forward control tests numerical sign/scale separately. The field run keeps x/z geometry, fixed mesh/regularization, predicted and observed resistance, signed residual, sensitivity/coverage and split indices in an ignored, checksummed `data/raw/ert/slagdump-m07-inverse-<code-sha>.json` receipt. No raw, model grid or per-reading array is committed.

Before fitting, every fifth quadrupole in spatial order **within each AB-index-span** is withheld. Because nearby Wenner arrays share electrodes, a second separate fit also withholds all quadrupoles whose A/B midpoint falls in the central 40-60% of the line. Each inverse must beat its own training-only homogeneous apparent-resistivity baseline by at least 10% on held-out log-resistance RMSE and stop by an engine criterion before its 12-iteration ceiling; an alternate mesh and doubled assumed errors are reported but never used to select the primary model. Because the file lacks measured errors, `σ_R = max(0.03|R|, 0.001 Ω)` is an explicit local weighting assumption, not an instrument estimate. The 3% value follows the provider's teaching example; the 0.001 Ω floor is a declared conservative modelling choice, not a source measurement. The local result records pyGIMLi log-Jacobian coverage divided by cell size, which is **not** model resolution. Even the blocked holdout remains within one profile and cannot establish independent-site transfer or true subsurface geology. 2D inversion assumes limited out-of-plane variation; regularization, mesh and error-floor changes can materially alter the recovered resistivity. A failed factor, inverse, or either holdout gate remains `not-converged`/`ineligible`, not an M07 success.

The [M07 feature SDD](../design/features/m07-slagdump-ert/requirements.md) names each gate. Only a separate reviewed rights decision could authorize a particular compact public aggregate; this branch publishes neither the field-derived result nor a raw mirror.

## Failure recovery and immutability

An unknown source ID or changed object URL is not accepted as an ad hoc download. Fetches require HTTPS on the reviewed Google Storage, raw GitHub and EarthScope hosts and reject redirects; a provider move calls for a ledger review and a new byte/hash receipt. A missing manual file prints the exact provider link and `--file` action; a metadata-only source prints its provider link and refuses acquisition. A wrong size/hash leaves the disputed input in place and installs nothing. An existing raw asset is always rehashed and never overwritten. A changed raw receipt or derivative hash halts processing for inspection. Tar entry paths, links, member count, bytes and expansion are bounded; the archive is never extracted to a directory. The entire external raw and local derivative tree is git-ignored; `git ls-files data/downloads data/raw` must be empty.

The acquisition layer establishes source and byte identity. The separate M07 script adds Slagdump-specific QC and offline numerical gates, but its local field result is not a public case or a claim of known geology. Koenigsee M09 and STEAD M13 remain separate work. Scientific publication still requires an explicit rights verdict for each derivative.
