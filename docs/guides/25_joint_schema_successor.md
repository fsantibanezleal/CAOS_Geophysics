## Exact schema and retained bytes

The predecessor is source-bound to the committed M01 physical forest. Its
root-family constraint admits existing gravity/MT/profile/waveform roots and
physical correction/transform children. The joint successor adds only the exact
root tuple `m11-native-members/v1`, `joint_gravity_magnetic_native`,
`geophysics.joint-native-dataset/v1`. All other literal columns, types, native
text/timestamps, rows, indexes and foreign keys survive unchanged. A root has
an actual immutable physical family; no missing-family bypass is permitted.

`app.joint_roots.register_root` is an explicit service for the allocated mount.
It verifies the source/payload/owner and selected literal schema, and inserts
family plus root inside the caller's existing write transaction. It neither
commits, copies/unlinks files nor grants numerical acceptance. The route uses
this service only when the parent passes it explicitly. Historical table-only
fixtures do not silently become allocated-schema evidence.

`joint_dataset_sources` retains every ordinary original dependency. The new
`joint_result_artifacts` model binds each member to the full immutable producing
job/owner/project/dataset/hash/method/request identity through a restrictive
composite FK. Original SHA, bounded length, closed relative member name and
exclusive owner/project/job storage key are mandatory. Deleting a job cannot
cascade away artifact custody. A schema row alone never verifies file bytes,
publication, charge release, completed inversion or scientific accuracy.

## Migration and rollback

Upgrade requires the exact committed0005 DDL, integrity/FK checks, no active
jobs, bounded rows and an explicit transactional SQLite delete/memory-journal
candidate. Foreign keys are disabled only by the explicit migration environment
before its transaction, checked before commit, then restored. DDL, row copy and
literal revision update share that transaction. No WAL target or autocommit
fallback is introduced.

Empty0006 may downgrade to0005 and restore its exact original DDL. Joint roots,
families, dependencies, jobs or artifacts refuse downgrade. Unknown successor
DDL refuses too. No file deletion or pathname-based charge relief happens.
M01's own0005->0004 downgrade remains forbidden; this leaf does not override it.

Tests bind immutable predecessor source and use only external generated SQL
candidates. They check plural owners/root variants, native row/type preservation,
actual round trip, complete artifact identity/check/FK enforcement, unknown/head/
active/custody negatives, every upgrade/downgrade cut and actual revision-update
cuts, plus original36-member root-family publication/rollback/source negatives.
These are storage/service gates, not canonical full lifecycle, host/WAL/power-loss
or original full24 scientific corrective acceptance.
