# Exact supplied dataset body and readable publication envelope

The protected magnetic client verifies the complete received UTF8 byte sequence
BEFORE decoding or JSON parsing. The selected authenticated dataset receipt's
sha256 is authoritative for that body. Request text/hash, matching IDs and
unchanged physics metadata do not replace the complete body hash. WebCrypto
hashes the original Uint8Array, never JSON.stringify output; cancellation is
rechecked after asynchronous hashing. The existing bounded transport stops
declared or streamed overflow before aggregate allocation.

The retained Python-produced nominal dataset control is74311 bytes, SHA256
`8938138fd485cd02a6e259530c5ebf94f7d7a8f6c8b3e3ffb6ffc4a4d2d1b343`.
That hash equals the independently retained selected receipt. The input control
has SHA256`3fcff61c3f53a70b2eba79a54edeb158079e6ae4f86d69ac8c0d37e8a7d3e660`.
It points to retained raw dataset bytes through an external fixture argument;
the tests do not reconstruct nominal bytes from its parsed payload. The raw
nominal body is distinct from the72583-byte altered metadata response used by
the independent adverse helper. Rejection of the latter does not by itself
prove nominal lexical compatibility.

It receives the retained raw file, verifies its full byte hash against the

qualification.

Publication, charged new dataset write, retained dataset read and browser
transport use the same8MiB (8388608 bytes) complete serialized body maximum.
The separate8MiB request maximum cannot stand in for it: JSON escaping and
geometry metadata can make the final dataset larger. Actual producer controls
parse a valid supplied request of exactly8MiB whose resulting dataset exceeds
8MiB, then refuse BEFORE creating a charged attempt, scratch or new dataset.
A retained oversized body is refused BEFORE parsing and preserved unchanged.

The historical attempt/debt inventory is different authority. Its16MiB
(16777216 bytes) known dataset-member cap and32MiB reservation are deliberately
unchanged. These bounds let an existing charged attempt remain accounted for;
they do not authorize publication, normal reads or client consumption above
8MiB. No unknown partial path is adopted, no existing oversized bytes are
deleted or rewritten, and no old attempt is silently upgraded. Request,
original,128MiB ZIP, scientific and native resource limits are not increased.
